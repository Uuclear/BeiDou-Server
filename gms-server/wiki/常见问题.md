# 常见问题（FAQ）

本文档收集了BeiDou冒险岛服务端在部署、开发、运行过程中常见的问题及解决方案。

## 一、启动相关问题

### 1.1 数据库连接失败

**问题描述**：启动时报数据库连接错误，控制台出现 `Communications link failure` 或 `Access denied for user` 等异常信息。

**可能原因**：
1. MySQL服务未启动
2. 数据库用户名或密码配置错误
3. MySQL版本不兼容（需MySQL 8.0+，不支持5.x）
4. 数据库端口被防火墙阻止
5. 数据库用户权限不足
6. JDBC URL配置错误（时区、字符集等）

**解决方案**：
1. 检查MySQL服务状态：
   - Windows：`net start mysql80`
   - Linux：`systemctl status mysqld` 或 `service mysql status`
2. 验证数据库账号密码：使用MySQL客户端手动连接测试
   ```bash
   mysql -u root -p
   ```
3. 确认MySQL版本：`mysql -V`，必须为8.0或以上
4. 检查 `application.yml` 配置：
   ```yaml
   mybatis-flex:
     datasource:
       mysql:
         url: jdbc:mysql://localhost:3306/beidou?useUnicode=true&characterEncoding=utf-8&useSSL=false&serverTimezone=Asia/Shanghai
         username: root
         password: your_password
   ```
5. 确保数据库用户拥有创建数据库和表的权限：
   ```sql
   GRANT ALL PRIVILEGES ON *.* TO 'root'@'localhost';
   FLUSH PRIVILEGES;
   ```
6. 首次启动无需手动创建数据库，服务端会自动创建 `beidou` 库

---

### 1.2 端口占用

**问题描述**：启动时报 `BindException: Address already in use` 或端口绑定失败。

**可能原因**：
1. 8484端口（登录服务器）被其他程序占用
2. 8686端口（Web API）被其他程序占用
3. 之前启动的服务端进程未正常关闭
4. 频道服务器端口范围冲突

**解决方案**：
1. 查找占用端口的进程：
   - Windows：
     ```cmd
     netstat -ano | findstr "8484"
     netstat -ano | findstr "8686"
     taskkill /F /PID <进程ID>
     ```
   - Linux/Mac：
     ```bash
     netstat -tlnp | grep -E "8484|8686"
     lsof -i :8484
     kill -9 <进程ID>
     ```
2. 检查是否有残留Java进程：
   ```bash
   jps -l
   # 或
   ps aux | grep java
   ```
3. 如需修改端口，编辑 `application.yml`：
   ```yaml
   server:
     port: 8686  # Web API端口
   gms:
     service:
       login-port: 8484  # 登录端口
   ```
4. IDEA启动时，确保没有多个运行实例同时启动

---

### 1.3 WZ加载失败

**问题描述**：启动时WZ相关报错，如 `FileNotFoundException`、`XML解析错误` 或怪物/地图数据加载失败。

**可能原因**：
1. `wz/` 目录不存在或文件缺失
2. 工作目录（Working directory）设置错误
3. WZ XML文件损坏或格式不正确
4. WZ文件路径包含中文或特殊字符

**解决方案**：
1. 确认目录结构：项目根目录下必须有 `wz/` 文件夹，包含：
   - Mob.wz/、Map.wz/、Npc.wz/、Item.wz/、Skill.wz、String.wz、Character.wz等
2. IDEA中设置正确的Working directory：
   - Run → Edit Configurations → Working directory 设置为 `$MODULE_WORKING_DIR$` 或 `gms-server` 目录绝对路径
3. 检查文件路径是否包含中文或空格，建议使用纯英文路径
4. 如果WZ文件缺失，重新从Release页面下载完整wz包
5. 检查控制台输出的具体错误文件名，确认该XML文件是否存在且格式正确

---

### 1.4 JDK版本错误

**问题描述**：启动时出现 `UnsupportedClassVersionError` 或编译/运行时版本不兼容错误。

**可能原因**：
1. 使用JDK版本低于21（如JDK 8、11、17）
2. JAVA_HOME环境变量指向错误的JDK版本
3. IDEA项目语言级别设置不正确
4. Maven编译使用的JDK版本与运行版本不一致

**解决方案**：
1. 检查当前Java版本：
   ```bash
   java -version
   javac -version
   ```
   必须显示版本号为21或以上
2. 配置JAVA_HOME环境变量指向JDK 21安装目录
3. IDEA中设置项目SDK：
   - File → Project Structure → Project SDK 选择 JDK 21
   - File → Project Structure → Project language level 选择 21
4. IDEA中设置Maven使用的JDK：
   - Settings → Build, Execution, Deployment → Build Tools → Maven → Runner → JRE 选择 JDK 21
5. 如果有多个JDK版本，确认PATH环境变量中JDK 21的bin目录优先级最高

---

## 二、客户端连接问题

### 2.1 客户端无法连接服务器

**问题描述**：客户端启动后显示"无法连接服务器"或卡在登录界面。

**可能原因**：
1. 服务端未正常启动
2. IP地址配置错误
3. 防火墙阻止连接
4. 客户端版本不匹配（需v83版本）
5. 端口映射/外网配置不正确
6. 登录器配置错误

**解决方案**：
1. 确认服务端已完全启动，控制台显示：
   ```
   Started ServerApplication in X.XXX seconds
   Login Server started on port 8484
   ```
2. 本地连接测试：使用 `telnet 127.0.0.1 8484` 测试端口连通性
3. 检查 `application.yml` 中的网络配置：
   ```yaml
   gms:
     service:
       wan-host: 127.0.0.1  # 外网IP需修改为实际公网IP
       lan-host: 127.0.0.1
       localhost: 127.0.0.1
   ```
4. 关闭防火墙或开放端口：
   - Windows防火墙：添加入站规则允许8484、8686端口
   - Linux：`firewall-cmd --add-port=8484/tcp --permanent && firewall-cmd --reload`
   - 云服务器：需在安全组中开放端口
5. 确认客户端是v83版本，且配套登录器配置的IP正确
6. 外网部署时，检查路由器端口映射是否正确

---

### 2.2 游戏中频繁断线

**问题描述**：玩家进入游戏后不久自动断开连接，或移动/攻击时掉线。

**可能原因**：
1. 网络不稳定
2. 服务端处理数据包时抛出异常
3. 心跳包超时设置过短
4. 内存溢出导致服务端崩溃
5. 加密密钥不匹配
6. 频道服务器异常关闭

**解决方案**：
1. 检查服务端控制台是否有异常堆栈信息，定位具体错误
2. 查看服务端日志文件（`logs/` 目录）中的错误记录
3. 确认网络连接质量，避免使用WiFi进行测试
4. 检查JVM内存设置，调整启动参数：
   ```bash
   java -Xms2g -Xmx4g -jar BeiDou.jar
   ```
5. 确认客户端版本与服务端版本完全匹配（v83）
6. 检查是否有频道服务器意外断开，查看Channel相关日志
7. 如果是特定操作导致断线（如使用某技能、进入某地图），可能是相关Handler存在bug

---

### 2.3 客户端版本不匹配

**问题描述**：连接时提示版本错误，或客户端显示"无法连接"但服务端无日志。

**可能原因**：
1. 客户端不是v83版本
2. 客户端补丁不完整
3. 服务端版本号配置与客户端不一致
4. Localhost测试IP被修改

**解决方案**：
1. 确认使用项目配套的v83客户端（从Release页面下载）
2. 检查服务端配置中的版本号（通常在常量类中定义）
3. 不要混用其他版本的客户端或服务端文件
4. 确认客户端的localhost.txt或登录器配置指向正确的服务器IP
5. 如果使用自定义客户端，需确保：
   - 版本号一致
   - 加密IV一致
   - 操作码（Opcode）一致

---

## 三、游戏内问题

### 3.1 怪物不刷新

**问题描述**：进入地图后看不到怪物，或击杀后不再刷新。

**可能原因**：
1. 地图WZ数据中怪物生成点配置错误
2. 怪物刷新任务未启动
3. 该地图的怪物数据不存在（Mob.wz中缺失）
4. 频道服务器刷怪定时器异常
5. 地图被设置为不刷怪

**解决方案**：
1. 检查控制台是否有刷怪相关错误日志
2. 确认对应地图的WZ XML文件中存在 `<life>` 节点配置怪物刷新点
3. 使用GM命令 `!spawn` 手动召唤怪物测试
4. 检查地图配置是否禁用了刷怪：`!mapinfo` 查看地图信息
5. 重启频道服务器或执行 `!reloadmap` 重载地图数据
6. 检查Mob.wz中是否存在对应怪物ID的XML文件
7. 查看刷怪管理器（MobSpawner）是否正常初始化

---

### 3.2 NPC没反应

**问题描述**：点击NPC没有对话窗口弹出，或NPC功能异常。

**可能原因**：
1. NPC脚本缺失或命名错误
2. 脚本语法错误导致执行失败
3. NPC ID与脚本文件名不匹配
4. 脚本引擎加载失败
5. 对话功能权限不足（某些NPC需要GM权限）

**解决方案**：
1. 检查 `scripts/npc/` 目录下是否存在对应NPC ID的脚本文件
   - 脚本文件名格式：`NPCID.js`（如 `1002000.js`）
2. 查看控制台是否有JavaScript脚本错误日志
3. 确认脚本使用正确的编码（UTF-8无BOM）
4. 使用GM命令 `!reloadscripts` 热重载所有脚本
5. 测试基础NPC（如市场管理员、转职官）是否正常，判断是个别脚本问题还是整体问题
6. 检查脚本是否正确调用了 `cm.start()` 或 `cm.sendNext()` 等对话方法
7. 查看脚本文件是否存在语法错误（括号不匹配、变量未定义等）

---

### 3.3 技能失效

**问题描述**：技能无法使用，或使用后无效果、无伤害。

**可能原因**：
1. 技能数据（Skill.wz）加载异常
2. 技能处理Handler存在bug
3. 职业/技能等级不满足要求
4. 技能冷却时间未结束
5. MP不足或前置技能未学习
6. 技能数据包操作码不匹配

**解决方案**：
1. 检查角色是否学习了该技能，且SP分配正确
2. 确认MP充足，且不在冷却/沉默/封印状态
3. 使用GM命令 `!skill <技能ID> <等级>` 重新学习技能测试
4. 查看控制台是否有技能相关异常日志
5. 检查Skill.wz中对应技能ID的XML数据是否完整
6. 确认技能类型与Handler处理逻辑匹配（近战/远程/魔法）
7. 检查服务端版本与客户端技能数据是否同步
8. 对于四转技能，确认是否已完成转职任务

---

### 3.4 背包异常

**问题描述**：物品无法移动、物品消失、背包格子显示异常、无法捡取物品。

**可能原因**：
1. 物品数据损坏
2. 背包数据同步异常
3. 物品ID不存在于Item.wz
4. 背包格子数量超过上限
5. 物品叠加逻辑错误
6. 客户端与服务端背包状态不一致

**解决方案**：
1. 重新登录角色，看是否恢复正常
2. 使用GM命令 `!clearinventory` 清理异常物品（谨慎使用）
3. 检查背包类型是否正确（装备/消耗/其他/设置/现金）
4. 查看控制台是否有背包操作相关错误
5. 确认物品ID在Item.wz中存在对应数据
6. 检查物品是否在冷却时间或交易限制状态
7. 如为特定物品异常，检查该物品的脚本或配置
8. 严重情况下可备份数据库后重建角色背包数据

---

## 四、脚本问题

### 4.1 脚本不生效

**问题描述**：修改脚本后重启或热重载，功能没有变化；或新添加的脚本无法被调用。

**可能原因**：
1. 脚本文件名错误（必须是NPC/功能ID）
2. 脚本放置目录错误
3. 未执行热重载命令
4. 脚本缓存未清除
5. 脚本中存在语法错误导致编译失败
6. 脚本编码错误（需UTF-8）
7. 脚本使用了不兼容的API

**解决方案**：
1. 确认脚本文件名正确：
   - NPC脚本：`scripts/npc/<NPCID>.js`
   - 任务脚本：`scripts/quest/<QUESTID>.js`
   - 地图脚本：`scripts/map/<MAPID>.js`
2. 检查脚本文件扩展名是否为 `.js`（注意不要有 `.js.txt`）
3. 执行热重载命令：`!reloadscripts`
4. 如热重载无效，尝试重启服务端
5. 使用文本编辑器检查脚本语法，确认无拼写错误
6. 确认脚本文件编码为UTF-8（无BOM）
7. 参考 `scripts/NPC Base.js` 模板脚本检查API调用是否正确
8. 查看控制台是否有脚本加载失败的错误信息

---

### 4.2 脚本报错

**问题描述**：触发脚本时控制台输出JavaScript错误，功能中断。

**可能原因**：
1. JavaScript语法错误（括号、引号不匹配）
2. 调用了不存在的方法（cm/qm对象方法名错误）
3. 访问空对象属性
4. 变量未定义
5. GraalVM JS引擎兼容问题
6. 脚本中使用了Java特有的语法但未正确导入

**解决方案**：
1. 仔细查看控制台错误信息，定位错误行号
2. 常见错误修复：
   - `SyntaxError`：检查括号、引号是否配对，语句是否完整
   - `ReferenceError`：变量未定义，检查变量名拼写
   - `TypeError`：访问null/undefined的属性，添加空值判断
3. 脚本开头检查cm/qm对象是否可用：
   ```javascript
   if (!cm) {
       cm = cm;
   }
   ```
4. 使用 `try-catch` 捕获异常便于调试：
   ```javascript
   try {
       // 脚本逻辑
   } catch(e) {
       cm.sendOk("脚本错误: " + e.message);
   }
   ```
5. 参考基础脚本模板（NPC Base.js）的写法
6. 确认使用的API在当前版本中存在（查看ScriptManager相关源码）

---

### 4.3 脚本热重载

**问题描述**：如何在不重启服务器的情况下更新脚本？热重载不生效怎么办？

**可能原因**：（使用说明+问题排查）

**使用方法**：
1. 在游戏中使用GM账号输入命令：`!reloadscripts`
2. 或在Web管理后台执行脚本重载
3. 控制台会输出脚本重载日志

**热重载不生效解决方案**：
1. 确认执行命令的账号拥有GM权限（权限等级需足够）
2. 修改脚本后保存文件，再执行重载命令
3. 如果是新增的脚本文件，可能需要重启服务端（热重载主要更新已加载的脚本）
4. 检查脚本文件名是否为纯数字ID（不要有空格或其他字符）
5. 部分核心脚本（如转职、商城）可能需要重启才能生效
6. 检查文件权限，确保服务端进程有读取脚本文件的权限
7. 如果使用IDEA开发，确认文件已保存到磁盘（不是仅在编辑器中修改）
8. 查看控制台是否输出"Reloaded all scripts"之类的成功日志

---

## 五、Web后台问题

### 5.1 登录失败

**问题描述**：访问Web管理后台（http://localhost:8686/swagger-ui 或gms-ui前端）无法登录，提示账号密码错误。

**可能原因**：
1. 默认账号密码错误
2. 账号被封禁
3. JWT配置错误
4. 数据库连接异常
5. Spring Security配置拦截

**解决方案**：
1. 默认管理员账号：`admin` / `admin`
2. 首次登录后请立即修改密码
3. 如果忘记密码，直接在数据库中重置：
   ```sql
   USE beidou;
   UPDATE accounts SET password = 'admin' WHERE name = 'admin';
   ```
   注意：密码存储格式可能是加密的，需查看密码加密方式
4. 检查 `application.yml` 中JWT配置：
   ```yaml
   jwt:
     secret: "your-uuid-secret"
     duration: 1800000
   ```
5. 确认Web API服务正常启动（8686端口）
6. 检查浏览器控制台是否有CORS错误，前后端端口需对应
7. 查看服务端日志中是否有认证失败的详细原因

---

### 5.2 API返回403 Forbidden

**问题描述**：调用API接口返回403状态码，提示权限不足。

**可能原因**：
1. 未携带JWT Token或Token已过期
2. Token格式错误
3. 账号权限等级不足
4. API路径权限配置不正确
5. IP被限制访问

**解决方案**：
1. 确认已登录并获取有效Token
2. 请求头中正确携带Authorization：
   ```
   Authorization: Bearer <your_token_here>
   ```
3. Token默认有效期30分钟，过期需重新登录
4. 检查账号GM权限等级：
   - 数据库中 `accounts` 表的 `gm` 字段
   - 最高权限gm=100或类似配置
5. 查看Spring Security配置类，确认API路径的权限设置
6. 开发环境可临时关闭权限验证方便调试（不建议生产环境）
7. Swagger UI测试时，点击"Authorize"按钮输入Token

---

### 5.3 Swagger无法访问

**问题描述**：访问 http://localhost:8686/swagger-ui/index.html 出现404或无法连接。

**可能原因**：
1. Swagger功能未开启（生产环境默认关闭）
2. 访问路径错误
3. Web服务未启动或端口错误
4. springdoc依赖缺失

**解决方案**：
1. 确认 `application.yml` 中已开启Swagger：
   ```yaml
   springdoc:
     api-docs:
       enabled: true
     swagger-ui:
       enabled: true
   ```
2. 正确的访问地址：`http://localhost:8686/swagger-ui/index.html`
3. 旧版本路径可能是 `/swagger-ui.html`，尝试访问该路径
4. 检查8686端口是否正常监听
5. 确认pom.xml中包含springdoc依赖：
   ```xml
   <dependency>
       <groupId>org.springdoc</groupId>
       <artifactId>springdoc-openapi-starter-webmvc-ui</artifactId>
   </dependency>
   ```
6. 生产环境建议关闭Swagger（设为false）以保证安全
7. 查看启动日志中是否有springdoc相关的初始化信息

---

## 六、性能问题

### 6.1 CPU占用过高

**问题描述**：服务端运行时CPU使用率持续较高（接近或超过100%）。

**可能原因**：
1. 死循环或无限递归
2. 定时任务执行过于频繁
3. 怪物刷新/AI计算量大
4. 在线玩家数量过多
5. 垃圾回收（GC）频繁
6. 脚本中存在性能问题
7. 日志输出级别过低（DEBUG模式大量输出）

**解决方案**：
1. 使用 `top`（Linux）或任务管理器（Windows）确认Java进程CPU占用
2. 使用JDK自带工具分析：
   ```bash
   jps  # 查找Java进程ID
   jstack <pid> > thread_dump.txt  # 导出线程堆栈
   jvisualvm  # 图形化监控CPU、线程
   ```
3. 检查是否有无限循环：查看线程栈中RUNNABLE状态的线程
4. 调整定时任务间隔：
   - 怪物刷新间隔
   - 角色保存间隔
   - 宠物饱满度下降间隔
5. 将日志级别调整为INFO或WARN：
   ```yaml
   logging:
     level:
       root: INFO
       org.gms: INFO
   ```
6. 限制单频道最大在线人数
7. 优化复杂脚本，避免在循环中执行频繁的数据库查询

---

### 6.2 内存泄漏

**问题描述**：服务端运行时间越长内存占用越高，最终出现 `OutOfMemoryError` 崩溃。

**可能原因**：
1. 集合类未清理（如Map、List只增不减）
2. 玩家对象未正常移除（离线后仍在内存）
3. 定时任务重复注册
4. 数据库连接未释放
5. 监听器/事件回调未注销
6. 缓存无限增长
7. Netty ByteBuf内存泄漏

**解决方案**：
1. 添加JVM启动参数，方便排查OOM：
   ```bash
   java -Xms2g -Xmx4g -XX:+HeapDumpOnOutOfMemoryError -jar BeiDou.jar
   ```
2. 使用 `jmap` 查看内存对象统计：
   ```bash
   jmap -histo <pid> | head -20
   ```
3. 使用MAT（Memory Analyzer Tool）分析堆转储文件（.hprof）
4. 检查以下常见泄漏点：
   - 玩家下线后是否从Channel的玩家列表中移除
   - 定时任务是否在玩家下线后取消
   - 事件监听器是否正确注销
   - Netty的ByteBuf是否正确释放（使用SimpleChannelInboundHandler）
5. 合理设置JVM堆内存大小，根据在线人数调整：
   - 测试环境：-Xms1g -Xmx2g
   - 小型私服（50人内）：-Xms2g -Xmx4g
   - 中型私服：-Xms4g -Xmx8g
6. 定期重启服务端（如每天凌晨）可暂时缓解

### 6.3 玩家多时卡顿

**问题描述**：在线玩家数量增加后，所有玩家都感觉操作延迟、卡顿。

**可能原因**：
1. 单频道承载人数过多
2. 主线程阻塞（Netty IO线程被耗时业务占用）
3. 数据库查询慢
4. 全局同步锁竞争
5. 地图内玩家/怪物数量过多
6. 广播消息过于频繁
7. 服务器硬件资源不足

**解决方案**：
1. 开启多频道（Channel）分散玩家压力
2. 确保业务逻辑不在Netty IO线程中执行：
   - 检查Handler中是否有耗时操作（如数据库查询、复杂计算）
   - 耗时任务应提交到业务线程池
3. 优化数据库查询：
   - 添加必要的索引
   - 避免频繁查询数据库，使用缓存
   - 批量操作替代单条操作
4. 减少不必要的全局广播：
   - 喇叭消息、公告消息频率控制
5. 优化地图内对象数量：
   - 热门地图限制刷怪数量
   - 及时清理掉落物
   - 限制单地图玩家人数
6. 使用缓存：
   - 玩家数据缓存
   - 物品/技能等WZ数据已缓存，检查是否重复加载
7. 升级服务器硬件或使用多服务器集群

## 七、开发相关问题

### 7.1 编译错误

**问题描述**：Maven编译失败，IDEA中出现红色错误提示。

**可能原因**：
1. JDK版本不正确（需JDK 21）
2. Maven依赖下载不完整
3. 代码存在语法错误
4. Lombok注解未被正确处理
5. 编码问题导致中文乱码
6. 项目未正确导入

**解决方案**：
1. 确认JDK版本为21，IDEA项目SDK和语言级别正确设置
2. 清理并重新下载依赖：
   ```bash
   mvn clean install -U
   ```
3. IDEA中重新导入Maven项目：右键pom.xml → Maven → Reload project
4. 确保已安装Lombok插件（IDEA插件市场搜索Lombok）
5. 开启注解处理器：
   - Settings → Build, Execution, Deployment → Compiler → Annotation Processors → Enable annotation processing
6. 检查文件编码设置为UTF-8：
   - Settings → Editor → File Encodings → 全部设置为UTF-8
7. 查看具体编译错误信息，修复代码问题
8. 如果是测试代码报错，可跳过测试编译：
   ```bash
   mvn clean package -DskipTests
   ```

### 7.2 依赖下载慢

**问题描述**：Maven下载依赖速度很慢，经常超时失败。

**可能原因**：
1. 使用Maven中央仓库（国外服务器）
2. 网络问题
3. 本地仓库损坏
4. 公司/学校网络代理问题

**解决方案**：
1. 配置Maven镜像源（阿里云镜像），编辑 `settings.xml`：
   ```xml
   <mirrors>
       <mirror>
           <id>aliyunmaven</id>
           <mirrorOf>*</mirrorOf>
           <name>阿里云公共仓库</name>
           <url>https://maven.aliyun.com/repository/public</url>
       </mirror>
   </mirrors>
   ```
2. settings.xml位置：
   - Windows：`C:\Users\用户名\.m2\settings.xml`
   - Linux/Mac：`~/.m2/settings.xml`
3. IDEA中确认使用的是正确的Maven配置：
   - Settings → Build Tools → Maven → User settings file
4. 如遇依赖损坏，删除本地仓库对应目录重新下载：
   - 本地仓库默认位置：`~/.m2/repository/`
5. 使用离线模式（如果之前已下载过依赖）：
   ```bash
   mvn -o clean package
   ```
6. 配置代理（如果在受限网络环境）

### 7.3 调试断点不命中

**问题描述**：在IDEA中设置断点，Debug模式启动后断点被跳过或提示"no executable code found"。

**可能原因**：
1. 编译后的class文件与源代码不匹配
2. 断点行号信息丢失
3. 代码热更新失败
4. 多线程环境下断点未命中
5. IDEA缓存问题

**解决方案**：
1. 清理并重新编译项目：
   - Build → Rebuild Project
   - 或 `mvn clean compile`
2. 确认Debug启动配置正确：
   - 使用Debug模式启动（不是Run模式）
   - 主类为 `org.gms.ServerApplication`
3. 关闭IDEA缓存并重启：
   - File → Invalidate Caches → Invalidate and Restart
4. 确认断点设置在可执行代码行（不要设在注释、空行、方法声明行）
5. 对于多线程问题，设置断点挂起策略为"Thread"而非"All"
6. 检查是否开启了代码混淆或优化（开发环境应关闭）
7. 在关键代码处添加日志输出辅助调试
8. 确认Working directory设置正确，否则类加载路径可能错误

## 八、部署相关问题

### 8.1 Linux部署问题

**问题描述**：在Linux服务器上部署时遇到各种问题。

**可能原因**：
1. Linux JDK安装配置错误
2. 文件权限问题
3. 缺少必要的系统库
4. 启动脚本无执行权限
5. 后台运行配置问题

**解决方案**：
1. 安装JDK 21（以Ubuntu为例）：
   ```bash
   apt update
   apt install openjdk-21-jdk
   java -version
   ```
2. 配置环境变量 `/etc/profile` 或 `~/.bashrc`：
   ```bash
   export JAVA_HOME=/usr/lib/jvm/java-21-openjdk-amd64
   export PATH=$JAVA_HOME/bin:$PATH
   ```
3. 上传服务端文件后设置权限：
   ```bash
   chmod +x launch.sh
   chmod -R 755 .
   ```
4. 检查文件是否完整（尤其是wz目录和脚本）
5. 使用nohup后台运行：
   ```bash
   nohup ./launch.sh > logs/stdout.log 2>&1 &
   ```
6. 或使用screen/tmux保持会话：
   ```bash
   screen -S gms
   ./launch.sh
   # Ctrl+A+D 分离会话
   ```
7. 查看启动日志排查问题：
   ```bash
   tail -f logs/stdout.log
   ```
8. 安装MySQL 8并配置远程访问（如需要）

### 8.2 外网访问配置

**问题描述**：本地可以连接但外网玩家无法连接服务器。

**可能原因**：
1. 公网IP配置错误
2. 路由器未做端口映射
3. 防火墙/安全组未开放端口
4. 使用了内网IP
5. ISP封端口
6. 没有公网IP（使用NAT）

**解决方案**：
1. 确认服务器有公网IP：
   - 访问 https://ifconfig.me 查看公网IP
   - 注意：云服务器的公网IP在操作系统内看到的是内网IP
2. 配置 `application.yml`：
   ```yaml
   gms:
     service:
       wan-host: 你的公网IP  # 如 123.45.67.89
       lan-host: 内网IP      # 如 192.168.1.100
   ```
3. 端口映射（家庭宽带）：
   - 登录路由器管理页面
   - 找到"虚拟服务器"或"端口映射"
   - 添加映射：外部端口8484 → 内部IP:8484（TCP）
   - 添加映射：外部端口8686 → 内部IP:8686（TCP）
4. 云服务器安全组配置：
   - 登录云服务商控制台
   - 找到安全组/防火墙规则
   - 添加入站规则：TCP 8484、8686端口允许0.0.0.0/0访问
5. 关闭系统防火墙或开放端口：
   ```bash
   # CentOS/RHEL
   firewall-cmd --permanent --add-port=8484/tcp
   firewall-cmd --permanent --add-port=8686/tcp
   firewall-cmd --reload
   
   # Ubuntu
   ufw allow 8484/tcp
   ufw allow 8686/tcp
   ```
6. 如果没有公网IP，可使用内网穿透工具（如frp、ngrok）或云服务器做中转

### 8.3 防火墙配置

**问题描述**：防火墙导致无法连接或部分功能异常。

**可能原因**：
1. Windows Defender防火墙阻止
2. Linux iptables/firewalld规则限制
3. 云服务商安全组拦截
4. 端口未全部开放（登录/频道/Web可能使用多个端口）

**解决方案**：
1. Windows防火墙添加入站规则：
   - 控制面板 → Windows Defender防火墙 → 高级设置
   - 入站规则 → 新建规则 → 端口 → TCP → 8484,8686,8787
   - 允许连接 → 勾选所有网络配置文件 → 命名并保存
2. 临时关闭防火墙测试（仅测试用）：
   - Windows：`netsh advfirewall set allprofiles state off`
   - Linux：`systemctl stop firewalld`
   - 测试完成后记得重新开启！
3. Linux firewalld开放端口：
   ```bash
   firewall-cmd --list-ports  # 查看已开放端口
   firewall-cmd --permanent --add-port=8484/tcp
   firewall-cmd --permanent --add-port=8686/tcp
   # 如果开启多频道，需开放频道端口范围
   firewall-cmd --permanent --add-port=8500-8600/tcp
   firewall-cmd --reload
   ```
4. 云服务器务必在控制台安全组中开放端口（系统防火墙开放还不够）
5. 如果频道端口是动态的，建议配置固定端口范围并全部开放
6. 使用telnet或nc命令测试端口连通性：
   ```bash
   telnet 服务器IP 8484
   nc -zv 服务器IP 8484
   ```
