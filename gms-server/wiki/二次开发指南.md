## 开发环境搭建

### 1. 系统要求

| 软件 | 版本要求 | 说明 |
|------|----------|------|
| JDK | 21+ | 项目使用Java 21，推荐使用GraalVM JDK以获得更好的JS脚本性能 |
| Maven | 3.8+ | 项目构建工具 |
| MySQL | 8.0+ | 数据库 |
| IDE | IntelliJ IDEA（推荐）/ Eclipse | 推荐使用IDEA，对Lombok和Spring Boot支持更好 |

### 2. IDE配置（IntelliJ IDEA）

#### 2.1 安装必要插件

确保安装以下插件：
- Lombok（必须，IDEA默认已集成）
- Maven Helper（可选，方便Maven依赖管理）
- .ignore（可选，Git忽略文件管理）
- JavaScript Support（必须，用于脚本开发）

#### 2.2 导入项目

1. 打开IDEA，选择 `File → Open`，选择项目根目录的 `pom.xml`
2. 等待Maven自动下载依赖（首次导入可能需要几分钟）
3. 配置项目SDK为JDK 21：`File → Project Structure → Project → SDK`

#### 2.3 启用注解处理

`File → Settings → Build, Execution, Deployment → Compiler → Annotation Processors` → 勾选 `Enable annotation processing`

#### 2.4 运行配置

创建Spring Boot运行配置：
- Main class: `org.gms.ServerApplication`
- Working directory: 项目根目录（确保能正确加载scripts、wz等目录）
- JVM参数（可选）：`-Xmx4G -Xms2G`（根据内存调整）

### 3. 数据库配置

1. 创建MySQL数据库：
```sql
CREATE DATABASE beidou DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
```

2. 修改 `src/main/resources/application.yml` 中的数据库连接信息：
```yaml
mybatis-flex:
  datasource:
    mysql:
      url: jdbc:mysql://localhost:3306/beidou?useUnicode=true&characterEncoding=utf-8&useSSL=false&serverTimezone=Asia/Shanghai
      username: root
      password: your_password
```

3. 首次启动时，Flyway会自动执行数据库迁移脚本创建表结构。

### 4. 调试技巧

#### 4.1 远程调试

在启动脚本中添加JVM调试参数：
```bash
java -agentlib:jdwp=transport=dt_socket,server=y,suspend=n,address=5005 -jar gms-server.jar
```

在IDEA中创建Remote JVM Debug配置，连接到端口5005即可远程调试。

#### 4.2 日志级别调整

在 `application.yml` 中调整日志级别：
```yaml
logging:
  level:
    root: INFO
    org.gms: DEBUG  # 游戏服务器日志
    org.gms.net: TRACE  # 网络数据包日志
```

## 代码规范

### 1. 命名规范

#### 1.1 Java类名

- 使用大驼峰命名法（PascalCase）
- Handler类以 `Handler` 结尾：`NPCTalkHandler`, `MovePlayerHandler`
- 命令类以 `Command` 结尾：`HealPersonCommand`, `WarpCommand`
- Service类以 `Service` 结尾：`CharacterService`, `ItemService`
- Controller类以 `Controller` 结尾：`AuthController`, `CharacterController`
- 实体类直接使用业务名：`Character`, `Account`, `Guild`
- 接口名通常是形容词或能力描述：`PacketHandler`, `ScriptManager`

#### 1.2 方法名

- 使用小驼峰命名法（camelCase）
- getter/setter遵循JavaBean规范：`getPlayer()`, `setLevel()`
- 布尔值判断使用is/has/can前缀：`isLoggedIn()`, `hasParty()`, `canWarp()`
- 业务方法使用动词开头：`healHpMp()`, `gainExp()`, `dropMessage()`

#### 1.3 变量名

- 使用小驼峰命名法
- 成员变量不要使用匈牙利命名法
- 常量使用全大写下划线分隔：`MAX_LEVEL`, `DEFAULT_PORT`
- 临时变量如循环变量可用i、j、k，但尽量使用有意义的名字

#### 1.4 包名

- 全部小写
- 按功能模块组织：`org.gms.net.server.channel.handlers`
- 不要使用复数形式：使用 `handler` 而非 `handlers`（但现有代码已有handlers包，保持一致即可）

### 2. 注释规范

#### 2.1 类注释

所有类必须包含类注释，说明类的职责：
```java
/**
 * 数据包处理器抽象基类
 * 提供了PacketHandler接口的默认实现，作为所有具体数据包处理器的父类
 * 默认验证客户端是否已登录状态，并提供获取服务器当前时间的工具方法
 *
 * @author OdinMS开发团队
 */
public abstract class AbstractPacketHandler implements PacketHandler {
```

#### 2.2 方法注释

公共API方法必须包含Javadoc注释：
```java
/**
 * 处理接收到的数据包
 *
 * @param p 输入数据包对象，包含数据包的具体数据内容
 * @param c 客户端连接对象，代表与客户端的连接会话
 */
void handlePacket(InPacket p, Client c);
```

#### 2.3 代码注释

- 复杂业务逻辑需要添加行内注释说明"为什么"而非"是什么"
- 不要添加无意义的注释
- 注释使用中文（面向国内开发者）

### 3. 代码风格

- 缩进使用4个空格，不要使用Tab
- 大括号采用K&R风格（左括号不换行）
- 每行不超过120个字符
- 导入包时不要使用通配符 `*`（静态导入除外）

## 添加新的数据包Handler

当需要处理客户端发送的新操作码时，需要添加新的PacketHandler。

### 1. 步骤概览

1. 确定操作码（RecvOpcode）
2. 创建Handler类继承 `AbstractPacketHandler`
3. 实现 `handlePacket` 方法
4. 在 `PacketProcessor` 中注册Handler
5. （可选）如果需要依赖，在 `ChannelDependencies` 中添加

### 2. 详细步骤

#### 步骤1：定义/确认RecvOpcode

在 `src/main/java/org/gms/net/opcodes/RecvOpcode.java` 中找到对应的操作码，如果是新的操作码需要添加：

```java
public enum RecvOpcode implements Opcode {
    // ... 现有操作码
    CUSTOM_PACKET(0x3CUSTOM),  // 自定义数据包
    ;
    
    private final int value;
    
    RecvOpcode(int value) {
        this.value = value;
    }
    
    @Override
    public int getValue() {
        return value;
    }
}
```

> **注意**：v83版本的操作码是固定的，自定义功能通常使用保留的操作码或CUSTOM_PACKET。

#### 步骤2：创建Handler类

在 `src/main/java/org/gms/net/server/channel/handlers/` 目录下创建新的Handler类：

```java
package org.gms.net.server.channel.handlers;

import org.gms.client.Client;
import org.gms.net.AbstractPacketHandler;
import org.gms.net.packet.InPacket;
import org.slf4j.Logger;
import org.slf4j.LoggerFactory;

/**
 * 自定义数据包处理器示例
 * 处理客户端发送的自定义功能请求
 */
public class CustomPacketHandler extends AbstractPacketHandler {
    private static final Logger log = LoggerFactory.getLogger(CustomPacketHandler.class);

    @Override
    public void handlePacket(InPacket p, Client c) {
        if (!c.isLoggedIn()) {
            return;
        }
        
        // 读取数据包内容
        byte type = p.readByte();
        int data = p.readInt();
        
        // 获取玩家对象
        var player = c.getPlayer();
        
        // 处理业务逻辑
        log.debug("收到自定义数据包: type={}, data={}, player={}", type, data, player.getName());
        
        // 示例：给玩家发送消息
        player.dropMessage("收到自定义数据包: " + type);
        
        // TODO: 实现具体功能
    }
}
```

#### 步骤3：在PacketProcessor中注册

编辑 `src/main/java/org/gms/net/PacketProcessor.java`，在 `registerChannelHandlers()` 方法中添加注册：

```java
private void registerChannelHandlers() {
    // ... 现有注册
    registerHandler(RecvOpcode.CUSTOM_PACKET, new CustomPacketHandler());
}
```

#### 步骤4：（可选）添加依赖注入

如果Handler需要使用Spring Bean（Service等），需要通过 `ChannelDependencies` 注入：

1. 在 `ChannelDependencies` 记录类中添加新的依赖：
```java
public record ChannelDependencies(
    NoteService noteService,
    FredrickProcessor fredrickProcessor,
    YourCustomService yourCustomService  // 添加你的服务
) {}
```

2. 在 `PacketProcessor.registerChannelHandlers()` 中使用：
```java
registerHandler(RecvOpcode.CUSTOM_PACKET, new CustomPacketHandler(channelDeps.yourCustomService()));
```

3. 修改Handler类接收依赖：
```java
public class CustomPacketHandler extends AbstractPacketHandler {
    private final YourCustomService yourCustomService;
    
    public CustomPacketHandler(YourCustomService yourCustomService) {
        this.yourCustomService = yourCustomService;
    }
    
    @Override
    public void handlePacket(InPacket p, Client c) {
        // 使用yourCustomService
    }
}
```

### 3. Handler基类说明

- `AbstractPacketHandler`：普通游戏内数据包的基类，默认验证登录状态
- `AbstractMovementPacketHandler`：移动相关数据包的基类
- `AbstractDealDamageHandler`：攻击伤害处理的基类

## 添加新的GM命令

GM命令是游戏内管理员使用的指令，通过聊天框输入 `!命令名 参数` 执行。

### 1. GM等级说明

| 等级 | 目录 | 权限说明 |
|------|------|----------|
| 0 | gm0 | 普通玩家可用命令 |
| 1 | gm1 | 初级GM |
| 2 | gm2 | 中级GM |
| 3 | gm3 | 高级GM/管理员 |
| 6 | gm6 | 超级管理员/开发者 |

### 2. 添加GM命令步骤

#### 步骤1：创建Command类

在对应等级的包下创建命令类，例如添加一个GM3命令 `!heal` 给玩家满血：

文件路径：`src/main/java/org/gms/client/command/commands/gm3/HealCommand.java`

```java
package org.gms.client.command.commands.gm3;

import org.gms.client.Character;
import org.gms.client.Client;
import org.gms.client.command.Command;
import org.gms.util.I18nUtil;

/**
 * 治疗命令 - 恢复指定玩家的HP和MP
 * 用法: !heal [玩家名] - 恢复指定玩家满血满蓝
 *       !heal - 恢复自己满血满蓝
 */
public class HealCommand extends Command {
    {
        setDescription("治疗自己或指定玩家，恢复满血满蓝");
    }

    @Override
    public void execute(Client c, String[] params) {
        Character player = c.getPlayer();
        
        if (params.length < 1) {
            // 没有参数，治疗自己
            player.healHpMp();
            player.message("你已经被治疗，HP/MP已恢复满！");
        } else {
            // 有参数，治疗指定玩家
            String targetName = params[0];
            Character target = c.getWorldServer().getPlayerStorage().getCharacterByName(targetName);
            
            if (target != null) {
                target.healHpMp();
                target.message("管理员 " + player.getName() + " 治疗了你！");
                player.message("已成功治疗玩家: " + targetName);
            } else {
                player.message("找不到玩家: " + targetName);
            }
        }
    }
}
```

#### 步骤2：命令自动注册

命令类会被自动扫描注册，无需手动注册！命令名由类名自动推导：
- 类名 `HealCommand` → 命令名 `!heal`
- 类名 `GiveMesosCommand` → 命令名 `!givemesos`
- 类名 `NPCCommand` → 命令名 `!npc`

#### 步骤3：（可选）添加国际化

在 `src/main/resources/i18n/` 对应的语言文件中添加消息：

`messages_zh_CN.properties`:
```properties
HealCommand.message1=治疗自己或指定玩家，恢复满血满蓝
HealCommand.success=已成功治疗玩家: {0}
HealCommand.notFound=找不到玩家: {0}
```

然后在代码中使用：
```java
player.message(I18nUtil.getMessage("HealCommand.success", targetName));
```

### 3. 命令参数处理

- `params[0]` 是第一个参数，以此类推
- 使用 `joinStringFrom(params, 0)` 可以将参数数组合并为字符串（从指定索引开始）
- 参数包含空格时，玩家需要用引号包裹

### 4. 命令示例：给玩家物品

```java
package org.gms.client.command.commands.gm3;

import org.gms.client.Character;
import org.gms.client.Client;
import org.gms.client.command.Command;
import org.gms.client.inventory.Item;
import org.gms.server.ItemInformationProvider;

/**
 * 给物品命令
 * 用法: !item <物品ID> [数量]
 */
public class ItemCommand extends Command {
    {
        setDescription("给予物品：!item <物品ID> [数量]");
    }

    @Override
    public void execute(Client c, String[] params) {
        Character player = c.getPlayer();
        
        if (params.length < 1) {
            player.message("用法: !item <物品ID> [数量]");
            return;
        }
        
        try {
            int itemId = Integer.parseInt(params[0]);
            int quantity = params.length >= 2 ? Integer.parseInt(params[1]) : 1;
            
            // 检查物品是否存在
            var itemInfo = ItemInformationProvider.getInstance();
            if (itemInfo.getName(itemId) == null) {
                player.message("物品ID不存在: " + itemId);
                return;
            }
            
            // 给予物品
            Item item = new Item(itemId(), (byte) 0, (short) quantity);
            player.gainItem(item);
            player.message("已获得物品: " + itemId + " x" + quantity);
            
        } catch (NumberFormatException e) {
            player.message("物品ID和数量必须是数字！");
        }
    }
}
```

## 添加新的WZ数据加载

WZ是冒险岛的资源文件格式，服务端使用XML格式的WZ数据。

### 1. WZ文件类型

在 `WZFiles.java` 中定义了支持的WZ类型：

```java
public enum WZFiles {
    STRING,
    MAP,
    MOB,
    NPC,
    ITEM,
    SKILL,
    CHARACTER,
    QUEST,
    REACTOR,
    ETC,
    // ... 添加新类型
}
```

### 2. 加载WZ数据示例

以下是加载并使用WZ数据的典型模式：

```java
import org.gms.provider.Data;
import org.gms.provider.DataProvider;
import org.gms.provider.DataProviderFactory;
import org.gms.provider.wz.WZFiles;
import org.gms.server.ItemInformationProvider;

public class CustomDataLoader {
    private static final Map<Integer, CustomData> customDataCache = new HashMap<>();
    
    public static void loadAll() {
        DataProvider dataProvider = DataProviderFactory.getDataProvider(WZFiles.ITEM);
        Data root = dataProvider.getData("Custom.img");
        
        if (root != null) {
            for (Data data : root.getChildren()) {
                int id = Integer.parseInt(data.getName());
                CustomData customData = new CustomData();
                
                // 读取各种类型的数据
                customData.setName(DataTool.getString(data.getChildByPath("name"), ""));
                customData.setLevel(DataTool.getInt(data.getChildByPath("level"), 0));
                customData.setDamage(DataTool.getIntConvert("damage", data, 0));
                
                // 读取向量/点
                Point pos = DataTool.getPoint(data.getChildByPath("pos"));
                
                // 读取子节点列表
                List<Integer> targets = new ArrayList<>();
                Data targetsData = data.getChildByPath("targets");
                if (targetsData != null) {
                    for (Data target : targetsData.getChildren()) {
                        targets.add(Integer.parseInt(target.getName()));
                    }
                }
                
                customDataCache.put(id, customData);
            }
        }
    }
    
    public static CustomData getCustomData(int id) {
        return customDataCache.get(id);
    }
}
```

### 3. DataTool常用方法

| 方法 | 说明 |
|------|------|
| `getString(data, default)` | 读取字符串值 |
| `getInt(data, default)` | 读取整数值 |
| `getShort(data, default)` | 读取短整数值 |
| `getFloat(data, default)` | 读取浮点值 |
| `getPoint(data)` | 读取坐标点(x,y) |
| `getIntConvert(path, parent, default)` | 从路径读取int |
| `getShortConvert(path, parent, default)` | 从路径读取short |

### 4. 注册WZ加载

在服务器启动时加载你的数据，可以在 `Server.java` 或相关的Manager类初始化时调用：

```java
// 在Server.init()或类似初始化方法中添加
CustomDataLoader.loadAll();
```

## 扩展Web API

Web API基于Spring Boot 3.x提供RESTful接口，默认端口8686。

### 1. API架构

- Controller层：处理HTTP请求，参数校验
- Service层：业务逻辑
- DTO层：数据传输对象（请求/响应）
- 使用Spring Security + JWT进行认证

### 2. 添加新的Controller

在 `src/main/java/org/gms/controller/` 下创建新的Controller：

```java
package org.gms.controller;

import io.swagger.v3.oas.annotations.Operation;
import io.swagger.v3.oas.annotations.tags.Tag;
import lombok.RequiredArgsConstructor;
import org.gms.model.dto.ResultBody;
import org.gms.service.CustomService;
import org.springframework.web.bind.annotation.*;

@RestController
@RequestMapping("/api/v1/custom")
@RequiredArgsConstructor
@Tag(name = "自定义功能", description = "自定义功能接口")
public class CustomController {
    
    private final CustomService customService;
    
    @GetMapping("/hello")
    @Operation(summary = "测试接口")
    public ResultBody<String> hello() {
        return ResultBody.success("Hello from custom API!");
    }
    
    @PostMapping("/data")
    @Operation(summary = "提交数据")
    public ResultBody<Void> submitData(@RequestBody SubmitDataDTO dto) {
        customService.processData(dto);
        return ResultBody.success();
    }
}
```

### 3. 创建DTO

在 `src/main/java/org/gms/model/dto/` 下创建请求/响应DTO：

```java
package org.gms.model.dto;

import lombok.Data;
import jakarta.validation.constraints.NotBlank;
import jakarta.validation.constraints.NotNull;

@Data
public class SubmitDataDTO {
    @NotBlank(message = "名称不能为空")
    private String name;
    
    @NotNull(message = "数值不能为空")
    private Integer value;
    
    private String description;
}
```

### 4. 创建Service

在 `src/main/java/org/gms/service/` 下创建Service：

```java

@Service
@RequiredArgsConstructor

    private final CharacterService characterService;  // 可以注入其他Service
    
    public void processData(SubmitDataDTO dto) {
        log.info("处理数据: name={}, value={}", dto.getName(), dto.getValue());
        
        // 业务逻辑处理
        // ...
    }
}
```

### 5. API权限控制

使用 `@PreAuthorize` 注解控制权限：

```java
import org.springframework.security.access.prepost.PreAuthorize;

@GetMapping("/admin-only")
@PreAuthorize("hasRole('ADMIN')")  // 需要管理员权限
public ResultBody<String> adminOnly() {
    return ResultBody.success("管理员接口");
}
```

### 6. 统一返回格式

所有API使用 `ResultBody` 统一返回格式：

```java
// 成功返回数据
return ResultBody.success(data);

// 成功无数据
return ResultBody.success();

// 失败返回
return ResultBody.error("错误消息");
return ResultBody.error(500, "服务器内部错误");
```

## 调试技巧

### 1. 日志配置

#### 1.1 开启数据包日志

在 `application.yml` 中配置：
```yaml
logging:
  level:
    org.gms.net.packet.logging: TRACE  # 开启数据包日志
```

#### 1.2 使用日志而非System.out

```java
// 错误示例
System.out.println("玩家进入地图: " + mapId);

// 正确示例
log.debug("玩家进入地图: {}", mapId);
log.info("服务器启动在端口: {}", port);
log.warn("配置文件缺失，使用默认值: {}", defaultValue);
log.error("数据库连接失败", e);
```

### 2. 数据包抓包

#### 2.1 使用内置PacketLogger

项目内置了数据包日志记录器，开启后会在控制台打印收发的数据包：

```java
// InPacketLogger.java - 入站数据包日志
// OutPacketLogger.java - 出站数据包日志
```

开启TRACE级别日志即可看到数据包内容。

#### 2.2 关键调试方法

## 代码调试常见问题

### 1. 客户端连接不上服务器

**排查步骤：**
1. 检查服务器是否正常启动，查看日志有无异常
2. 检查端口是否开放：`netstat -an | grep 8484`
3. 检查 `application.yml` 中的 `wan-host`、`lan-host` 配置是否正确
4. 检查防火墙设置
5. 确认客户端版本是v83，服务端配置的版本号匹配

### 2. 数据包Handler不触发

**可能原因：**
1. 忘记在 `PacketProcessor` 中注册Handler
2. Opcode值不对，对照RecvOpcode检查
3. Handler的 `validateState()` 返回false（比如没登录就发游戏内包）
4. 加了断点但没放开，导致数据包超时

### 3. 脚本不生效

**排查步骤：**
1. 脚本文件名是否正确（NPC脚本是NPC ID.js）
2. 脚本语法错误，查看控制台日志的JS错误
3. 脚本有没有放到正确的目录（scripts/npc/, scripts/quest/等）
4. 尝试执行 `!reloadevents` 重新加载脚本
5. 检查脚本编码是否为UTF-8

### 4. NullPointerException空指针

**常见原因：**
1. `c.getPlayer()` 返回null - 检查是否已登录
2. `c.getChannelServer()` 返回null - 检查频道初始化
3. 数据库查询返回null - 记得做null检查

**最佳实践：**
```java
Character player = c.getPlayer();
if (player == null) {
    log.warn("Player is null for client");
    return;
}

MapleMap map = player.getMap();
if (map == null) {
    log.warn("Map is null for player {}", player.getName());
    return;
}
```

### 5. 物品不显示/属性不对

**排查步骤：**
1. 检查WZ文件是否存在且正确加载
2. 检查物品ID是否正确
3. 查看ItemInformationProvider是否正确加载了物品数据
4. 检查背包是否满了，物品可能无法获得

### 6. 数据库相关问题

**常见问题：**
1. **表不存在**：检查Flyway迁移是否正常执行，查看启动日志
2. **连接超时**：检查MySQL服务是否启动，连接地址、端口、用户名密码是否正确
3. **中文乱码**：确保数据库和连接字符串都使用utf8mb4编码

#### 2.2 启动脚本

**Linux启动脚本 (start.sh)：**
```bash
#!/bin/bash
APP_NAME=gms-server.jar
APP_HOME=/opt/gms
LOG_FILE=$APP_HOME/logs/server.log
PID_FILE=$APP_HOME/gms.pid

# JVM参数
JAVA_OPTS="-Xms2G -Xmx4G -XX:+UseG1GC -XX:MaxGCPauseMillis=200"
JAVA_OPTS="$JAVA_OPTS -Dspring.profiles.active=prod"
JAVA_OPTS="$JAVA_OPTS -agentlib:jdwp=transport=dt_socket,server=y,suspend=n,address=*:5005"

case "$1" in
    start)
        if [ -f $PID_FILE ]; then
            echo "Server is already running!"
            exit 1
        fi
        echo "Starting $APP_NAME..."
        nohup java $JAVA_OPTS -jar $APP_HOME/$APP_NAME > $LOG_FILE 2>&1 &
        echo $! > $PID_FILE
        echo "Server started with PID $!"
        ;;
    stop)
        if [ ! -f $PID_FILE ]; then
            echo "Server is not running!"
            exit 1
        fi
        PID=$(cat $PID_FILE)
        echo "Stopping server (PID: $PID)..."
        kill $PID
        rm -f $PID_FILE
        echo "Server stopped."
        ;;
    restart)
        $0 stop
        sleep 5
        $0 start
        ;;
    status)
        if [ -f $PID_FILE ]; then
            PID=$(cat $PID_FILE)
            if ps -p $PID > /dev/null; then
                echo "Server is running, PID: $PID"
            else
                echo "PID file exists but server not running. Cleaning up."
                rm -f $PID_FILE
            fi
        else
            echo "Server is not running."
        fi
        ;;
    *)
        echo "Usage: $0 {start|stop|restart|status}"
        exit 1
        ;;
esac
```

### 3. systemd服务配置（推荐）

创建 `/etc/systemd/system/gms-server.service`：

```ini
[Unit]
Description=BeiDou MapleStory Server
After=network.target mysql.service

[Service]
Type=simple
User=gms
WorkingDirectory=/opt/gms
ExecStart=/usr/bin/java -Xms2G -Xmx4G -XX:+UseG1GC -Dspring.profiles.active=prod -jar gms-server.jar
Restart=on-failure
RestartSec=10
StandardOutput=journal+console
StandardError=journal+console

[Install]
WantedBy=multi-user.target
```

使用systemctl管理服务：
```bash
sudo systemctl daemon-reload

sudo systemctl start gms-server
sudo systemctl status gms-server

```
