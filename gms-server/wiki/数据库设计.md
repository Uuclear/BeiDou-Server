# GMS Server 数据库设计文档

## 1. 数据库概述

### 1.1 基本信息

| 项目 | 说明 |
|------|------|
| 数据库类型 | MySQL 8.0+ |
| 存储引擎 | InnoDB（主要）、MyISAM（部分高频读取表） |
| 字符集 | utf8mb4 |
| 排序规则 | utf8mb4_general_ci |
| 版本管理 | Flyway 数据库迁移工具 |

### 1.2 Flyway 版本管理

数据库使用 Flyway 进行版本控制，迁移脚本位于 `src/main/resources/db/migration/` 目录下，命名规则为：

- `V{版本号}__{描述}.sql` - 版本化迁移脚本
- 例如：`V1.0.0__create_accounts.sql`、`V1.7.0__create_game_config.sql`

版本从 V1.0.0 开始，后续版本持续迭代新增表结构和数据。

### 1.3 命名规范

- 表名：小写字母+下划线，如 `inventoryitems`、`game_config`
- 字段名：小写字母+下划线，如 `characterid`、`config_type`
- 主键：统一使用 `id` 作为自增主键字段名
- 外键关联：使用 `{表名单数}id` 格式，如 `accountid`、`characterid`

### 4.1 核心实体关系

accounts (1) ───< (N) characters
    │                    │

    │                    ├──< skills

### 4.2 主要关联关系

| 主表 | 从表 | 外键字段 | 关系 | 说明 |
|------|------|----------|------|------|

| guilds | characters | leader | 1:1 | 家族族长 |

| shops | shopitems | shopid | 1:N | 商店物品 |
| gachapon_reward_pool | gachapon_reward | pool_id | 1:N | 奖池奖励 |
| characters | bosslog_daily | characterid | 1:N | 每日BOSS记录 |

### 4.3 物品流转关系

物品是游戏中最复杂的实体，其在不同表之间的流转关系如下：

1. **模板**：物品数据从WZ文件加载，`itemid`为模板ID
2. **掉落**：`drop_data`/`drop_data_global`/`reactordrops`配置掉落规则
3. **拾取**：进入`inventoryitems`（characterid或accountid非空）
4. **装备**：装备类物品关联`inventoryequipment`记录附加属性
5. **存储**：存入`storages`或`fredstorage`
6. **交易**：通过`duey`快递或直接交易转移
7. **商店**：NPC商店出售，`shops`/`shopitems`定义商店物品
8. **商城**：点券购买，关联`nxcode`/`gifts`/`wishlists`
9. **转蛋机**：`gachapon_reward_pool`/`gachapon_reward`定义奖池

## 5. 数据库扩展建议

### 5.1 性能优化建议

1. **读写分离**
   - `drop_data`已使用MyISAM适合高频读取
   - 日志表（bosslog、famelog等）可考虑按时间分表
   - 考虑主从复制，读操作走从库

2. **索引优化**
   - `characters`表的`name`字段建议加索引（角色名搜索频繁）
   - `inventoryitems`的`itemid`字段建议加索引（物品查询）
   - 日志表按时间字段加索引便于清理

3. **分表策略**
   - `inventoryitems`数据量大，可考虑按`characterid % N`分表
   - 日志表按月份分表（如`bosslog_daily_202401`）
   - 聊天、邮件等历史数据定期归档

### 5.2 功能扩展建议

1. **新功能表设计规范**
   - 所有新表使用InnoDB引擎
   - 统一使用utf8mb4字符集
   - 必须有`id`自增主键
   - 包含`create_time`和`update_time`时间戳字段
   - 外键字段加索引

2. **推荐新增表**
   - `login_log`：登录日志表，记录每次登录的IP、HWID、时间
   - `item_log`：物品流转日志，记录物品获取/消耗/转移
   - `chat_log`：聊天日志（需要开启use_enable_chat_log）
   - `cashshop_transactions`：商城购买记录表
   - `guild_board`：家族留言板表（替代现有bbs相关表）

3. **数据统计扩展**
   - 新增`statistics_daily`表，每日统计活跃用户、在线峰值
   - 新增`player_stats`表，记录角色每日副本、击杀、经济数据
   - 考虑增加数据仓库层用于报表分析

### 5.3 数据安全建议

1. **数据备份**
   - 每日全量备份 + 实时binlog备份
   - 账号密码已使用BCrypt加密，确保密钥安全
   - 敏感配置（如数据库密码）使用环境变量注入

2. **数据清理**
   - 定期清理过期日志（bosslog、famelog等保留3-6个月）
   - 清理超过保留期的过期物品（expiration字段）
   - 清理长时间未登录的账号（建议1年以上）

3. **审计日志**
   - 所有GM操作应记录审计日志
   - 点券/金币大额变动记录日志
   - 封禁/解封操作保留操作人记录

### 5.4 Flyway迁移规范

1. **版本命名**
   - 主版本号.次版本号.修订号（如V1.0.0、V1.10.1）
   - 大版本号对应大的功能模块
   - 禁止修改已发布的迁移脚本

2. **脚本编写**
   - 使用`CREATE TABLE IF NOT EXISTS`避免重复执行
   - 数据迁移使用幂等写法（INSERT IGNORE、ON DUPLICATE KEY UPDATE）
   - 每个脚本前添加注释说明用途
   - 大表DDL变更考虑使用pt-online-schema-change

3. **配置数据管理**
   - `game_config`配置新增使用版本化迁移
   - `command_info`命令变更使用迁移脚本
   - 初始数据和测试数据分离
