# 核心模块详解

本文档详细说明 GMS Server 的核心模块实现原理和关键代码。

## 一、网络模块详解

网络模块基于 Netty 4.1.109 实现，负责处理客户端连接、数据包加解密、数据包分发等核心网络通信功能。

### 1.1 服务器架构

服务器采用多端口架构，分为登录服务器和频道服务器：

- **LoginServer（登录服务器）**：监听 `login-port`（默认 8484），处理账号登录、世界选择、频道选择、角色选择等登录流程
- **ChannelServer（频道服务器）**：每个频道监听一个端口，处理游戏内所有逻辑（移动、攻击、聊天、NPC 对话等）
- **Web API 服务器**：基于 Spring Boot Undertow，监听 8686 端口，提供 Web 管理后台 RESTful API

核心类位置：
- `org.gms.net.netty.AbstractServer`：抽象服务器基类
- `org.gms.net.netty.LoginServer`：登录服务器
- `org.gms.net.netty.ChannelServer`：频道服务器
- `org.gms.net.server.Server`：服务器主类，管理整个服务器生命周期

### 1.2 Netty Pipeline 配置

当客户端连接时，Netty Pipeline 按以下顺序配置处理器（`ServerChannelInitializer.setUpHandlers()`）：

1. **IdleStateHandler**：空闲状态检测，30秒无数据传输则断开连接
2. **PacketCodec**：数据包编解码器（核心），负责数据包的加密解密和解析
3. **SendPacketLogger**：发送数据包日志记录（可选，调试用）
4. **ReceivePacketLogger**：接收数据包日志记录（可选，调试用）
5. **Client**：客户端处理器，最终处理业务逻辑

### 1.3 加密解密机制

冒险岛使用自定义的加密算法保证通信安全：

- **握手阶段**：连接建立后，服务器生成发送 IV 和接收 IV，通过未加密的 Hello 包发送给客户端
- **MapleAESOFB**：AES OFB（输出反馈）模式加密，这是主要的加密算法
- **MapleCustomEncryption**：冒险岛自定义的滚动加密，对数据包头部进行额外加密
- **InitializationVector**：IV 管理，每次发送/接收数据包后 IV 会滚动更新
- **PacketEncoder**：出站数据包编码器，按协议加密数据
- **PacketDecoder**：入站数据包解码器，解密并解析数据包长度

核心类位置：`org.gms.net.encryption` 包

### 1.4 数据包结构

每个游戏数据包遵循以下结构：

```
[长度(4字节)] [头部(4字节)] [数据(N字节)]
```

- **长度**：数据包总长度（不包含长度字段本身）
- **头部**：包含操作码（opcode）和序列号，用于校验和路由
- **数据**：具体业务数据，按冒险岛协议序列化

数据包接口：
- `org.gms.net.packet.Packet`：数据包基础接口
- `org.gms.net.packet.InPacket`：入站数据包接口，提供读取方法（readByte, readShort, readInt, readLong, readString 等）
- `org.gms.net.packet.OutPacket`：出站数据包接口，提供写入方法（writeByte, writeShort, writeInt, writeLong, writeString 等）
- `org.gms.net.packet.ByteBufInPacket`/`ByteBufOutPacket`：基于 Netty ByteBuf 的实现

### 1.5 Handler 机制

数据包通过 PacketProcessor 路由到对应的 Handler 处理：

1. **PacketProcessor**：数据包处理器，维护 opcode → PacketHandler 的映射表
   - `getLoginServerProcessor()`：获取登录服务器处理器
   - `getChannelServerProcessor(world, channel)`：获取频道服务器处理器

2. **PacketHandler 接口**：所有数据包处理器实现此接口
   ```java
   public interface PacketHandler {
       void handlePacket(InPacket p, Client c);  // 处理数据包
       boolean validateState(Client c);          // 验证客户端状态是否合法
   }
   ```

3. **AbstractPacketHandler**：抽象基类，提供通用验证逻辑

4. **处理器分类**：
   - `org.gms.net.server.handlers.login`：登录阶段处理器（登录、选服、选角、创建角色等）
   - `org.gms.net.server.channel.handlers`：游戏内处理器（移动、攻击、聊天、NPC、背包等，共 100+ 个 Handler）

## 二、角色系统详解

角色系统是游戏的核心，`Character` 类是整个服务器最复杂的类之一。

### 2.1 Character 类核心字段

Character 类位于 `org.gms.client.Character`，核心字段包括：

**基础信息：**
- `id`：角色唯一 ID（数据库主键）
- `accountId`：所属账号 ID
- `world`：所在世界 ID
- `name`：角色名称
- `gender`：性别（0男/1女）
- `skinColor`：肤色
- `hair`：发型 ID
- `face`：脸型 ID
- `level`：等级（1~200+）
- `job`：职业（Job 枚举）
- `fame`：人气值
- `mapId`：当前地图 ID

**属性点：**
- `str`/`dex`/`int`/`luk`：基础属性（力量/敏捷/智力/幸运）
- `hp`/`mp`：当前 HP/MP
- `maxHp`/`maxMp`：最大 HP/MP
- `remainingAp`：剩余属性点（AP）
- `remainingSp`：各技能剩余技能点（SP）数组

**经验与升级：**
- `exp`：当前经验值
- `expTable`：经验值表（`org.gms.constants.game.ExpTable`，存储各级升级所需经验）

**位置信息：**
- `position`：当前坐标（Point）
- `stance`：姿态
- `foothold`：当前立足点 ID

**背包与装备：**
- `inventory`：背包数组（EQUIP, USE, SETUP, ETC, CASH, EQUIPPED）
- `equipped`：已装备物品映射

**社交相关：**
- `buddyList`：好友列表
- `party`：所属队伍
- `guild`：所属公会
- `guildRank`：公会职位
- `family`/`familyEntry`/`familyId`：家族
- `messenger`：聊天窗
- `marriedWith`：结婚对象 ID

**技能与 Buff：**
- `skills`：已学习技能映射（skillId → SkillEntry）
- `buffStats`/`buffEff`：当前 Buff 状态
- `cooldowns`：技能冷却映射
- `diseases`：疾病/异常状态
- `skillMacros`：技能宏列表

**其他：**
- `gmLevel`：GM 权限等级（0~6）
- `meso`：金币
- `monsterBook`：怪物图鉴
- `quests`：任务状态
- `keymap`/`quickslot`：快捷键
- `mount`：骑宠
- `pets`：宠物列表

### 2.2 职业系统

职业通过 `org.gms.client.Job` 枚举定义，主要职业分支：

| 职业系列 | 一阶 | 二阶 | 三阶 | 四阶 |
|---------|------|------|------|------|
| **新手** | 初心者(0) | - | - | - |
| **战士** | 战士(100) | 剑客/准骑士/枪战士(110/120/130) | 勇士/骑士/龙骑士(111/121/131) | 英雄/圣骑士/黑骑士(112/122/132) |
| **法师** | 魔法师(200) | 火毒/冰雷/牧师(210/220/230) | 火毒巫师/冰雷巫师/祭司(211/221/231) | 火毒魔导师/冰雷魔导师/主教(212/222/232) |
| **弓箭手** | 弓箭手(300) | 猎人/弩弓手(310/320) | 游侠(311/321) | 神射手/箭神(312/322) |
| **飞侠** | 飞侠(400) | 刺客/侠客(410/420) | 无影人/独行客(411/421) | 隐士/侠盗(412/422) |
| **海盗** | 海盗(500) | 拳手/枪手(510/520) | 斗士/大副(511/521) | 冲锋队长/船长(512/522) |
| **骑士团** | 初心者(1000) | 魂骑士/炎术士/风灵使者/夜行者/奇袭者 | - | - |
| **战神** | 战童(2000) | 战神(2100/2110/2111/2112) | - | - |

职业判断方法：`Job.isWarrior()`, `Job.isMagician()`, `Job.isBowman()`, `Job.isThief()`, `Job.isPirate()` 等。

### 2.3 属性系统

角色属性计算涉及多个部分：

1. **基础属性**：AP 分配的 str/dex/int/luk
2. **装备加成**：装备提供的属性（武器攻击力、魔法攻击力、防御力、回避、命中、速度、跳跃等）
3. **Buff 加成**：技能 Buff 提供的临时属性（BuffStat 枚举定义了所有可加成的属性）
4. **属性计算**：`getTotalStr()`, `getTotalDex()`, `getTotalInt()`, `getTotalLuk()`, `getTotalWatk()`, `getTotalMatk()` 等方法计算最终属性

BuffStat 枚举使用位掩码（long 类型，共 64+ 位）高效存储 Buff 状态，例如：
- `WATK(0x100000000L)`：武器攻击力加成
- `MATK(0x400000000L)`：魔法攻击力加成
- `WDEF/MDEF`：物理/魔法防御
- `ACC/AVOID/SPEED/JUMP`：命中/回避/速度/跳跃
- `STUN/POISON/SEAL/DARKNESS/WEAKEN`：异常状态
- `WATK/MATK/WDEF/MDEF/ACC/AVOID/SPEED/JUMP` 等基础属性 Buff

### 2.4 升级机制

升级流程：

1. **经验获取**：击杀怪物、完成任务获取经验值
2. **升级检查**：`levelUp()` 方法检查当前 exp 是否达到升级所需经验（ExpTable 表中存储）
3. **等级提升**：level +1，HP/MP 增长，获得 AP 和 SP
4. **AP 分配**：玩家可手动将 AP 分配到 str/dex/int/luk/hp/mp
5. **SP 分配**：玩家可将 SP 加到技能上（`DistributeSPHandler` 处理）
6. **转职**：达到特定等级后可进行转职（如 30级二转、70级三转、120级四转）

经验表位置：`org.gms.constants.game.ExpTable`

## 三、背包物品系统

### 3.1 Inventory 类

`org.gms.client.inventory.Inventory` 管理单个背包类型的物品：

**背包类型（InventoryType 枚举）：**
- `UNDEFINED(-1)`：未定义
- `EQUIP(1)`：装备栏
- `USE(2)`：消耗栏（药水、卷轴、飞镖等）
- `SETUP(3)`：设置栏（椅子、坐骑等）
- `ETC(4)`：其他栏（怪物掉落物、任务物品等）
- `CASH(5)`：现金栏（点装、商城物品）
- `EQUIPPED(-1)`：已装备栏（特殊）

**核心字段：**
- `inventory: Map<Short, Item>`：物品存储，key 为槽位（slot），value 为物品对象
- `type: InventoryType`：背包类型
- `slotLimit: byte`：槽位上限（通过背包扩张券可增加）
- `lock: ReentrantLock`：公平锁，保证线程安全

**核心方法：**
- `addItem(item)`：添加物品（自动堆叠可叠加物品）
- `removeItem(slot, quantity)`：移除物品
- `moveItem(sSource, sTarget)`：移动物品
- `getItem(slot)`：获取指定槽位物品
- `findById(itemId)`：按物品 ID 查找
- `isFull()`：背包是否已满
- `getNextFreeSlot()`：获取下一个空闲槽位

### 3.2 Item 类

`org.gms.client.inventory.Item` 是所有物品的基类：

**核心字段：**
- `id: int`：物品 ID（对应 WZ 中的物品 ID）
- `position: short`：背包槽位
- `quantity: short`：数量（装备固定为1，可叠加物品可堆叠）
- `flag: short`：标志位（不可交易、账号共享、宿命剪刀等）
- `expiration: long`：过期时间戳（-1 表示永不过期）
- `owner: String`：物品所有者名称（刻名装备）
- `cashId: int`：现金物品唯一 ID
- `sn: int`：商城序列号
- `petid: int`：宠物 ID（如果是宠物）
- `giftFrom: String`：礼物赠送者

**物品类型判断：**
通过 `org.gms.constants.inventory.ItemConstants` 工具类判断：
- `isEquip(itemId)`：是否为装备
- `isUse(itemId)`：是否为消耗品
- `isSetup(itemId)`：是否为设置物品
- `isEtc(itemId)`：是否为其他物品
- `isCash(itemId)`：是否为现金物品
- `isWeapon(itemId)`：是否为武器
- `isArmor(itemId)`：是否为防具
- `isPet(itemId)`：是否为宠物
- `isRechargeable(itemId)`：是否为可充值飞镖/子弹

### 3.3 Equip 类

`org.gms.client.inventory.Equip` 继承自 Item，表示装备：

**装备额外属性：**
- `upgradeSlots: byte`：可升级次数（砸卷次数）
- `level: byte`：装备等级（强化等级）
- `str/dex/int/luk: short`：装备属性加成
- `watk/matk: short`：武器/魔法攻击力
- `wdef/mdef: short`：物理/魔法防御力
- `acc/avoid: short`：命中/回避
- `hands/speed/jump: short`：手技/速度/跳跃
- `hp/mp: short`：HP/MP 加成
- `ringId: int`：戒指 ID
- `cosmetic: boolean`：是否为点装
- `viciousHammer: byte`：金锤子次数
- `itemLevel: byte`：装备等级（潜能系统）
- `itemExp: int`：装备经验

**装备强化：**
- **卷轴强化**：使用卷轴提升装备属性（成功率、失败可能破坏装备）
- **金锤子**：增加可升级次数
- **潜能**：装备附加潜能属性
- **星岩**：高级装备强化系统

StatUpgrade 枚举表示装备属性的升级变化。

### 3.4 背包操作

`org.gms.client.inventory.manipulator.InventoryManipulator` 提供静态方法操作背包：
- `addFromDrop()`：从掉落添加物品
- `removeAll()`：移除所有物品
- `checkSpace()`：检查是否有空间
- 各种物品增删改查的静态工具方法

## 四、地图与怪物系统

### 4.1 MapleMap 类

`org.gms.server.maps.MapleMap` 表示游戏中的一张地图：

**核心字段：**
- `id: int`：地图 ID
- `portals: List<MapleMapPortal>`：传送点列表
- `footholds: Map<Integer, Foothold>`：立足点映射
- `footholdTree: FootholdTree`：立足点树（用于快速查找角色脚下的地面）
- `characters: Map<Integer, Character>`：地图内的玩家（objectId → Character）
- `monsters: Map<Integer, Monster>`：地图内的怪物
- `npcs: Map<Integer, NPC>`：地图内的 NPC
- `drops: Map<Integer, MapItem>`：地图上的掉落物品
- `reactors: Map<Integer, Reactor>`：反应器（敲击物）
- `spawnPoints: List<SpawnPoint>`：怪物刷新点
- `mapObjects: Map<MapObjectType, Map<Integer, MapObject>>`：所有地图对象分类存储

**地图对象类型（MapObjectType）：**
- PLAYER：玩家
- MONSTER：怪物
- NPC：NPC
- ITEM：掉落物品
- DOOR：门/时空门
- SUMMON：召唤兽
- SHOP：商店
- MINI_GAME：迷你游戏
- MIST：毒雾/技能雾
- REACTOR：反应器
- PLAYER_NPC：玩家 NPC
- HIRED_MERCHANT：雇佣商人
- PLAYER_SHOP：个人商店

**核心方法：**
- `spawnMonster(monster)`：刷新怪物
- `spawnNPC(npc)`：刷新 NPC
- `removeMapObject(mapObject)`：移除地图对象
- `moveMonster(monster, newPos)`：移动怪物
- `damageMonster(chr, monster, damage)`：对怪物造成伤害
- `killMonster(killer, monster, highestDamageChar)`：击杀怪物，处理掉落和经验
- `spawnDrop(drop, position)`：刷新掉落物
- `killAllMonsters()`：击杀所有怪物
- `getNearestPlayer(pos)`：获取最近的玩家

### 4.2 Monster 类

`org.gms.server.life.Monster` 表示怪物：

**核心字段（来自 MonsterStats）：**
- `id: int`：怪物 ID（模板 ID）
- `name: String`：怪物名称
- `level: byte`：等级
- `maxHp/maxMp: int`：最大 HP/MP
- `hp/mp: int`：当前 HP/MP
- `exp: int`：击杀经验
- `pad/mad: int`：物理/魔法攻击力
- `pdd/mdd: int`：物理/魔法防御力
- `acc/avoid: int`：命中/回避
- `speed: int`：移动速度
- `flySpeed: int`：飞行速度
- `undead: boolean`：是否亡灵系
- `boss: boolean`：是否为 BOSS
- `elementalEffectiveness: Map<Element, ElementalEffectiveness>`：元素抗性
- `skills: List<MobSkill>`：怪物技能
- `drops: List<MonsterDropEntry>`：掉落列表
- `position: Point`：当前位置
- `foothold: int`：当前立足点

**怪物技能：**
- `MobSkill`：怪物技能定义
- `MobSkillType`：技能类型（物理攻击、魔法攻击、状态异常、回复等）
- 怪物会在特定条件下释放技能（如 BOSS 放技能）

### 4.3 刷新机制

怪物刷新由 `SpawnPoint` 管理：

1. **怪物刷新点（SpawnPoint）**：
   - 每个地图有多个刷新点，来自 WZ 数据
   - `monsterId: int`：刷新的怪物 ID
   - `position: Point`：刷新位置
   - `nextPossibleSpawn: long`：下次可刷新时间
   - `spawnedMonsters: List<Integer>`：已刷新的怪物 objectId 列表

2. **刷新流程：**
   - 怪物死亡后，刷新点设置冷却时间
   - 定时任务（`MapMonitor` 或频道定时任务）定期检查
   - 当冷却结束且地图内怪物数量未满时，重新刷新怪物
   - BOSS 通常有更长的刷新冷却时间

### 4.4 掉落系统

击杀怪物后，根据掉落表计算掉落物：

1. **掉落数据：**
   - `MonsterDropEntry`：单个怪物掉落条目（物品 ID、掉落概率、最低等级、最高等级等）
   - `MonsterGlobalDropEntry`：全局掉落（所有怪物都可能掉的物品，如卷轴、怪物卡）
   - `ReactorDropEntry`：反应器掉落

2. **掉落计算：**
   - 遍历掉落列表，根据概率随机判定是否掉落
   - 受到掉率倍率（活动掉落卡、双倍掉率、祭祀的花等）影响
   - 考虑玩家等级与怪物等级差（等级差过大降低掉率）
   - 考虑组队加成（组队时掉落分配）

3. **掉落物品（MapItem）：**
   - 掉落后在地图上显示，玩家可拾取
   - 有归属权（击杀者优先拾取）
   - 超时后自动消失（被其他玩家拾取或清除）
   - 金币直接分配给击杀者（或组队分配）

## 五、NPC 对话系统

NPC 对话系统基于 GraalVM JavaScript 脚本引擎实现，支持灵活的对话流程控制。

### 5.1 NPCConversationManager

`org.gms.scripting.npc.NPCConversationManager` 是 NPC 脚本与服务器交互的核心类，继承自 `AbstractPlayerInteraction`，提供完整的 NPC 对话 API：

**核心字段：**
- `npc: int`：当前对话的 NPC ID
- `npcOid: int`：NPC 在地图中的 objectId
- `scriptName: String`：脚本文件名（可选）
- `getText: String`：玩家在文本输入框输入的文本
- `itemScript: boolean`：是否为物品脚本
- `otherParty: List<PartyCharacter>`：组队对话的其他队员
- `nextLevelContext: NextLevelContext`：多级对话上下文

### 5.2 对话类型

NPC 对话支持多种交互方式：

1. **普通对话（sendNext/next）：**
   - 显示文本内容，点击下一句继续
   - `cm.sendNext(text)`：发送下一句文本
   - `cm.sendNextS(text, skin)`：带表情的对话
   - `cm.sendOk(text)`：只有确定按钮的对话

2. **是/否选择（sendYesNo）：**
   - 显示文本和是/否按钮
   - `cm.sendYesNo(text)` → 玩家选择后调用 `cm.getNextAction()` 获取结果（0=是，1=否）

3. **选项选择（sendSimpleChoose/sendStyle）：**
   - 显示选项列表让玩家选择
   - `cm.sendSimpleChoose(text, options)` → 玩家选择后返回选项索引
   - `cm.sendStyle(text, styles)`：选择发型/脸型等

4. **数字输入（sendGetNumber）：**
   - 显示数字输入框
   - `cm.sendGetNumber(text, defaultValue, min, max)` → `cm.getNumber()` 获取输入

5. **文本输入（sendGetText）：**
   - 显示文本输入框
   - `cm.sendGetText(text)` → `cm.getText()` 获取输入

6. **图片展示（sendAvatarData）：**
   - 展示角色外观
   - 转职、整容等场景使用

### 5.4 脚本加载

NPC 脚本位于 `scripts/npc/` 或 `scripts-zh-CN/npc/` 目录，文件名为 `{npcId}.js`：

### 6.2 SkillEntry 与技能等级

角色的技能通过 `Map<Integer, SkillEntry> skills` 存储：

```java
public class SkillEntry {
    private final Skill skill;
    private int skilevel;      // 当前技能等级
    private byte masterLevel;  // 能手册决定的最高等级

```

### 6.3 BuffStat 与 Buff 效果

BuffStat 枚举（`org.gms.client.BuffStat`）使用 long 位掩码标识 Buff 状态，共 80+ 种 Buff/Debuff：

**属性增益类：**
- `WATK(0x100000000L)`：武器攻击力
- `MATK(0x400000000L)`：魔法攻击力
- `WDEF(0x200000000L)`/`MDEF(0x800000000L)`：物理/魔法防御
- `ACC(0x1000000000L)`/`AVOID(0x2000000000L)`：命中/回避
- `SPEED(0x8000000000L)`/`JUMP(0x10000000000L)`：移动速度/跳跃力
- `HANDS(0x4000000000L)`：手技

**技能效果类：**
- `MAGIC_GUARD(0x20000000000L)`：魔法盾（魔法盾吸收伤害）
- `DARKSIGHT(0x40000000000L)`：隐身术
- `BOOSTER(0x80000000000L)`：快速武器（攻击加速）
- `POWERGUARD(0x100000000000L)`：伤害反击
- `HYPERBODYHP(0x200000000000L)`/`HYPERBODYMP(0x400000000000L)`：神圣之火（HP/MP 上限提升）
- `INVINCIBLE(0x800000000000L)`：无敌
- `SOULARROW(0x1000000000000L)`：无形箭（不消耗箭矢）
- `COMBO(0x20000000000000L)`：连击
- `WK_CHARGE(0x40000000000000L)`：属性Charges
- `DRAGONBLOOD(0x80000000000000L)`：龙之魂
- `HOLY_SYMBOL(0x100000000000000L)`：神圣祈祷（经验加成）
- `SHADOWPARTNER(0x400000000000000L)`：影子伙伴
- `MAPLE_WARRIOR(0x8L)`：冒险岛勇士（全属性百分比加成）
- `STANCE(0x10L)`：稳如泰山（不被击退）
- `SHARP_EYES(0x20L)`：锐利之眼（暴击率提升）
- `MANA_REFLECTION(0x40L)`：魔法反射
- `ECHO_OF_HERO(0x8000L)`：英雄回声

**异常状态类（Debuff）：**
- `STUN(0x2000000000000L)`：眩晕
- `POISON(0x4000000000000L)`：中毒
- `SEAL(0x8000000000000L)`：封印（无法使用技能）
- `DARKNESS(0x10000000000000L)`：黑暗（命中率降低）
- `WEAKEN(0x4000000000000000L)`：虚弱
- `SLOW(0x200000000L)`：减速
- `CURSE(...)`：诅咒
- `BLIND(0x1000L)`：致盲
- `CONFREEZE(...)`：冰冻

Buff 生效时：
1. 将 BuffStat 位进行 OR 操作写入 buffStats 字段
2. 记录 Buff 数值（如 WATK +20）到 buffEff
3. 发送 Buff 封包给客户端显示 Buff 图标
4. Buff 到期或取消时清除对应位

### 8.2 命令注册方式

命令通过继承 `org.gms.client.command.Command` 抽象类实现：

```java
public abstract class Command {
    protected int rank;           // 所需权限等级
    protected String description; // 命令描述
    
    public abstract void execute(Client client, String[] params);
}
```

命令存储在 `CommandsExecutor.registeredCommands` HashMap 中（命令名 → Command 实例），启动时自动扫描并实例化 gm0~gm6 包下所有 Command 子类。

命令从数据库加载（通过 `CommandService`），支持 Web 后台动态管理命令权限。

### 8.4 命令执行流程

1. 玩家在聊天框输入命令（以 `@` 或 `!` 开头）
2. `MultiChatHandler` 检测到是命令，调用 `CommandsExecutor.handle()`
3. `CommandsExecutor.isCommand()` 判断是否为命令格式
4. 解析命令名和参数，命令名转小写
5. 从 registeredCommands 查找对应 Command
6. 检查玩家 gmLevel 是否 >= command.getRank()
7. 权限通过则执行 `command.execute(client, params)`
8. 记录命令执行日志

监狱地图（JAIL，MapId.JAIL）中的非 GM 玩家无法使用任何命令。
