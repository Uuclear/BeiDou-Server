# 项目架构

本文档详细介绍BeiDou（北斗）冒险岛服务端的整体架构设计。

## 核心组件详解

### 1. 网络通信层 (net包)

网络层基于Netty 4.x实现，负责处理与游戏客户端的所有TCP通信。

#### 1.1 服务器类型

| 服务器 | 类 | 默认端口 | 职责 |
|--------|-----|----------|------|
| 登录服务器 | LoginServer | 8484 | 处理账号登录、服务器列表、频道选择 |
| 频道服务器 | ChannelServer | 动态端口 | 处理游戏内所有交互（移动、攻击、聊天、NPC等） |

#### 1.2 数据包处理流程

```
客户端发送数据 → Netty接收 → PacketDecoder解码 → 
  MapleAESOFB解密 → PacketProcessor路由 → 
    对应PacketHandler处理 → 业务逻辑执行 → 
      PacketEncoder编码 → MapleAESOFB加密 → Netty发送 → 客户端接收
```

#### 1.3 加密协议

冒险岛使用自定义的加密算法：
- **MapleAESOFB**: AES-OFB模式加密（初始化向量IV随版本变化）
- **MapleCustomEncryption**: 自定义滚动加密（用于数据包头）
- 每个连接（登录/频道）使用独立的加密上下文

相关代码位于 [net/encryption](file:///workspace/gms-server/src/main/java/org/gms/net/encryption/) 包。

### 2. 游戏世界模型

#### 2.1 World（世界/大区）

[World.java](file:///workspace/gms-server/src/main/java/org/gms/net/server/world/World.java) 代表一个游戏大区/服务器世界：
- 管理多个频道（Channel）
- 管理跨频道社交系统：好友、公会、组队、聊天、拍卖等
- 负责世界范围的事件广播

#### 2.2 Channel（频道）

[Channel.java](file:///workspace/gms-server/src/main/java/org/gms/net/server/channel/Channel.java) 代表一个游戏频道：
- 管理该频道内所有在线玩家
- 管理地图（Map）、怪物（Mob）、NPC、掉落物（Drop）等
- 处理几乎所有游戏内数据包（约150+个Handler）
- 包含各种定时任务：怪物刷新、宠物饱满度、自动保存等

#### 2.3 Character（角色）

[Character.java](file:///workspace/gms-server/src/main/java/org/gms/client/Character.java) 代表一个游戏玩家角色：
- 角色属性：等级、经验、力量/敏捷/智力/运气、HP/MP等
- 背包系统：装备栏、消耗栏、其他栏、设置栏、现金栏
- 技能系统：技能等级、冷却时间、增益效果
- 社交关系：好友、公会、组队、家族
- 状态系统：Buff/Debuff、疾病、冷却

### 3. 数据包处理器（Handlers）

[net/server/channel/handlers](file:///workspace/gms-server/src/main/java/org/gms/net/server/channel/handlers/) 包含约150个数据包处理器，每个处理器对应客户端的一种操作：

| 类别 | 主要Handler |
|------|------------|
| 移动 | MovePlayerHandler, MoveLifeHandler, MovePetHandler, MoveSummonHandler |
| 战斗 | CloseRangeDamageHandler, RangedAttackHandler, MagicDamageHandler |
| 交互 | NPCTalkHandler, NpcAnimationHandler, ChangeMapHandler, ItemPickupHandler |
| 背包 | ItemMoveHandler, InventoryMergeHandler, InventorySortHandler, ScrollHandler |
| 社交 | GeneralChatHandler, WhisperHandler, MultiChatHandler, GuildOperationHandler |
| 组队/好友 | PartyOperationHandler, BuddylistModifyHandler, DenyPartyRequestHandler |
| 商店/NPC | FredrickHandler, StorageHandler, DueyHandler, HiredMerchantRequest |
| 现金商城 | CashOperationHandler, EnterCashShopHandler, CouponCodeHandler |
| 任务/技能 | QuestActionHandler, DistributeAPHandler, DistributeSPHandler, SkillEffectHandler |

每个Handler实现 `PacketHandler` 接口的 `handlePacket(InPacket, Client)` 方法。

### 4. 脚本引擎层

使用GraalVM JS引擎执行JavaScript脚本，支持游戏内容的热更新而无需重启服务器：

| 脚本类型 | 目录 | 管理器类 | 说明 |
|----------|------|----------|------|
| NPC脚本 | scripts/npc/ | NPCScriptManager | NPC对话、商店、传送 |
| 任务脚本 | scripts/quest/ | QuestScriptManager | 任务开始/完成逻辑 |
| 事件脚本 | scripts/event/ | EventScriptManager | 活动副本、任务事件 |
| 传送门脚本 | scripts/portal/ | PortalScriptManager | 传送门触发逻辑 |
| 反应堆脚本 | scripts/reactor/ | ReactorScriptManager | 地图机关/宝箱触发 |
| 地图脚本 | scripts/map/ | MapScriptManager | 地图进入/离开事件 |
| 物品脚本 | scripts/item/ | ItemScriptManager | 物品使用效果 |

脚本中注入了 `cm`（NPC对话管理器）/`qm`（任务管理器）等对象，提供丰富的API。

### 5. WZ资源加载

WZ是冒险岛的资源文件格式，本服务端使用解析后XML格式：

[provider/wz](file:///workspace/gms-server/src/main/java/org/gms/provider/wz/) 包：
- **XMLWZFile**: 加载WZ XML文件
- **XMLDomMapleData**: 解析XML DOM结构
- **WZFiles**: 定义WZ文件类型（String, Map, Mob, NPC, Item, Skill, Character等）
- **DataTool**: 提供数据读取的工具方法

WZ资源包含：
- Mob.wz: 怪物数据（属性、技能、掉落、动画）
- Npc.wz: NPC数据（形象、对话位置）
- Map.wz: 地图数据（地形、怪物点、NPC点、传送门、反应堆、出生点）
- Item.wz: 物品数据（装备属性、消耗品效果）
- Skill.wz: 技能数据（伤害、延迟、效果、动画）
- String.wz: 字符串资源（物品名、地图名、NPC名、怪物名）
- Character.wz: 角色外观（发型、脸型、武器、衣服等）

### 7. 数据持久层

#### 7.1 ORM: MyBatis-Flex

使用MyBatis-Flex作为ORM框架：
- 实体类位于 [dao/entity](file:///workspace/gms-server/src/main/java/org/gms/dao/entity/) 包（80+张表）
- Mapper接口位于 [dao/mapper](file:///workspace/gms-server/src/main/java/org/gms/dao/mapper/) 包，继承BaseMapper获得基础CRUD
- 支持QueryWrapper进行复杂查询

#### 7.2 数据库迁移: Flyway

数据库版本迁移脚本位于 `src/main/resources/db/migration/`，启动时自动执行：
- V1.0.0__create_accounts.sql: 账号表
- V1.0.6__create_characters.sql: 角色表
- V1.0.15__create_guilds.sql: 公会表
- 等等共70+个迁移脚本

#### 7.3 连接池: Druid

使用阿里巴巴Druid连接池，提供监控和性能优化。

## 多线程模型

服务端使用多线程模型以支持高并发：

1. **Netty Boss/Worker线程组**: 处理网络IO事件
2. **定时任务线程**: 
   - 角色自动保存（默认每隔一段时间保存在线角色数据）
   - 怪物刷新
   - 宠物饱满度下降
   - 事件调度
3. **事件执行线程**: 服务器事件管理器的任务执行
4. **Spring Boot线程**: Web API请求处理

## 启动流程

```
ServerApplication.main()
  ↓
1. initDb() - 解析application.yml，自动创建数据库
  ↓
2. SpringApplication.run() - Spring容器初始化
  ├─ 配置类加载 (GameConfig, ServerConfig, I18nConfig...)
  ├─ Bean初始化
  ├─ Flyway迁移执行
  ├─ MyBatis-Flex Mapper扫描
  └─ ServerManager初始化
  ↓
3. Server启动 (net.server.Server)
  ├─ 初始化世界(World)
  ├─ 加载WZ资源
  ├─ 启动LoginServer (端口8484)
  ├─ 启动ChannelServer(s)
  ├─ 注册Channel到World
  ├─ 启动定时任务
  └─ 启动Web API (端口8686)
  ↓
服务器启动完成，等待客户端连接
```

## 关键设计模式

| 模式 | 应用场景 |
|------|----------|
| 工厂模式 | CharacterFactory（角色创建）、PacketCreator（数据包创建） |
| 单例模式 | World、各种Manager、WZ资源缓存 |
| 策略模式 | PacketHandler（不同数据包用不同Handler处理） |
| 观察者模式 | CharacterListener（角色事件监听） |
| 模板方法 | AbstractScriptManager（脚本管理器基类） |
| 生产者-消费者 | 事件调度系统 |
