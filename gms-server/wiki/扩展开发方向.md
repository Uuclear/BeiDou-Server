# 扩展开发方向

本文档梳理BeiDou冒险岛服务端未来可开发的功能方向，为开发者提供参考和规划。每个方向包含**现状分析**、**目标**和**实现思路**。

## 一、游戏内容扩展方向

### 1.1 新职业

**现状**：目前服务端基础框架已支持冒险家职业体系，部分职业技能和转职流程可能未完全实现。

**目标**：完整实现所有v83版本职业，并可扩展后续版本特色职业。

**实现思路**：
1. **职业数据完善**：
   - 从WZ文件中提取各职业技能数据，补全Skill.wz中缺失的技能配置
   - 完善技能效果实现：攻击、Buff、召唤物、持续伤害等
   - 实现四转全技能（含技能册、能手册系统）
2. **转职系统完善**：
   - 各职业1-4转转职任务脚本
   - 转职NPC对话、转职地图、转职道具验证
   - 技能点（SP）自动分配与重置
3. **特色职业扩展**：
   - 骑士团（魂骑士、炎术士、风灵使者、夜行者、奇袭者）
   - 战神（Aran）combo连击系统
   - 龙神（Evan）多段转职与龙的技能
   - 暗影双刀（Dual Blade）双刀武器系统
4. **技能系统重构**：
   - 抽象技能效果处理器，使用策略模式处理不同技能类型
   - 实现技能冷却组、技能延迟、技能取消机制
   - 完善Buff/Debuff状态系统：持续时间、叠加规则、驱散逻辑
5. **代码实现参考**：
   - 技能处理器：`net.server.channel.handlers.SkillEffectHandler`
   - 技能效果类：`client.status`包
   - 技能数据：`provider.wz`包的Skill数据解析

### 1.2 新地图

**现状**：WZ中包含全量地图数据，但部分地图脚本、事件、NPC未配置。

**目标**：开放更多地图区域，补充地图特色玩法。

**实现思路**：
1. **地图基础配置**：
   - 检查Map.wz中所有地图数据完整性
   - 配置地图怪物刷新点（life节点）
   - 配置地图NPC位置（npc节点）
   - 配置传送门（portal节点）与跳转关系
2. **主题副本/地图**：
   - 蘑菇城主题副本（30-38级）
   - 废都广场主题副本（35-50级）
   - 克里塞主题副本（50-70级）
   - 天空之城、玩具城、神木村等经典区域完善
3. **高级地图开放**：
   - 时间神殿系列地图
   - 未来金银岛
   - Boss地图：扎昆、暗黑龙王、品克缤等前置地图
4. **地图事件脚本**：
   - 编写地图进入/离开触发脚本（`scripts/map/`）
   - 反应堆（Reactor）事件脚本：机关、宝箱、传送装置
   - 定时事件：地图内定时刷新特殊怪物、掉落道具
5. **小地图/小地图标识**：
   - 配置小地图图片数据
   - 实现小地图NPC/队友/怪物标记
6. **代码实现参考**：
   - 地图加载：`server.maps.Map`
   - 刷怪：`server.life.MobSpawner`
   - 传送门：`server.maps.Portal`

### 1.4 新任务系统完善

**现状**：基础任务框架已支持，但任务脚本覆盖率低，许多任务无法接取或完成。

**目标**：实现v83版本全任务，包含任务剧情、需求验证、奖励发放。

**实现思路**：
1. **任务数据梳理**：
   - 从String.wz提取任务名称、描述、完成对话文本
   - 整理任务需求配置：等级、职业、前置任务、物品需求、怪物击杀
   - 整理任务奖励：经验、金币、物品、人气、技能点
2. **任务脚本编写**：
   - 每个任务独立脚本文件：`scripts/quest/<任务ID>.js`
   - 使用qm（QuestManager）API：
     ```javascript
     qm.startQuest();
     qm.completeQuest();
     qm.haveItem(itemId, count);
     qm.gainItem(itemId, count);
     qm.gainExp(exp);
     qm.getPlayer().gainMeso(meso);
     ```
3. **任务类型支持**：
   - 普通对话任务
   - 物品收集任务
   - 怪物击杀任务
   - 跑腿传话任务
   - 组队任务前置
   - 转职任务
   - 技能获取任务
   - 重复任务
   - 活动任务
4. **任务UI完善**：
   - 任务可接/可完成提示灯泡
   - 任务日志窗口分类
   - 任务追踪功能
   - 任务导航（小地图箭头）
5. **批量任务生成工具**：
   - 开发脚本批量生成简单任务模板
   - 优先完成转职、技能、剧情主线任务
6. **代码实现参考**：
   - 任务管理器：`scripting.quest.QuestScriptManager`
   - 任务动作处理器：`net.server.channel.handlers.QuestActionHandler`
   - 基础模板：`scripts-zh-CN/QUEST Base.js`

### 1.5 活动系统

**现状**：有基础事件框架，但缺乏可配置的活动系统。

**目标**：实现可配置、可热更新的活动系统，支持节日活动、限时活动、日常活动。

**实现思路**：
1. **活动配置化**：
   - 活动配置文件（YAML/JSON）：
     ```yaml
     activities:
       - id: christmas_event
         name: 圣诞节活动
         type: festival
         start-time: 2024-12-24 00:00:00
         end-time: 2024-12-26 23:59:59
         buffs:
           - skillId: 11121000  # 双倍经验
             duration: 3600000
         drops:
           - itemId: 4001126  # 圣诞礼盒
             chance: 0.05
         maps: [100000000, 100000001]  # 活动地图
     ```
2. **活动类型**：
   - **节日活动**：春节、圣诞、万圣节、周年庆
   - **日常活动**：双倍经验、双倍掉率、跑环任务
   - **周末活动**：GM活动、BOSS攻城、答题活动
   - **限时活动**：特殊副本开放、现金道具折扣
3. **活动功能模块**：
   - 活动时间表/日历
   - 活动Buff自动施放
   - 活动特殊掉落
   - 活动商店/兑换NPC
   - 活动任务链
   - 全服公告提醒
4. **活动管理API**：
   - GM命令开启/关闭活动
   - Web后台活动配置与监控
   - 活动参与统计
   - 活动奖励发放工具
5. **热更新支持**：
   - 修改活动配置无需重启
   - 实时生效（活动脚本重载）
6. **代码实现参考**：
   - 定时任务：`server.TimerManager`
   - 世界广播：`server.world.World`
   - GM命令：`client.command.Commands`

## 二、功能完善方向

### 2.1 交易系统完善

**现状**：基础玩家交易已有，但缺少部分交易限制和安全机制。

**目标**：完善交易系统，防止交易漏洞，增加更多交易方式。

**实现思路**：
1. **交易安全**：
   - 交易物品锁定确认机制（防止交易外挂）
   - 交易倒计时二次确认
   - 交易日志记录（交易双方、物品、时间、IP）
   - 可疑交易检测（短时间内大额物品转移）
2. **交易限制**：
   - 等级限制交易（防止小号转移赃物）
   - 物品交易限制：不可交易物品、装备后绑定、灵魂绑定
   - 现金道具交易限制
   - 交易冷却时间
3. **新增交易方式**：
   - 个人商店（Hired Merchant）：
     - 玩家开设离线商店
     - 商店精灵雇佣
     - 商店搜索功能
   - 快递系统（Duey）：
     - 物品寄送
     - 到付邮件
     - 邮件附件
   - 礼物系统：现金商城道具赠送
4. **交易黑名单/拒收**：
   - 屏蔽特定玩家交易请求
   - 拒绝陌生人交易
5. **代码实现参考**：
   - 交易Handler：`net.server.channel.handlers.PlayerInteractionHandler`
   - 玩家互动：`server.maps`包下PlayerShop等

### 2.2 拍卖系统

**现状**：拍卖基础框架可能已有，但功能不完整。

**目标**：实现功能完善的拍卖系统，支持物品寄售、搜索、竞拍。

**实现思路**：
1. **拍卖核心功能**：
   - 物品上架：设置起拍价、一口价、拍卖时长
   - 物品搜索：按名称、类型、等级、价格区间搜索
   - 竞拍机制：出价记录、自动出价、竞拍超时处理
   - 一口价购买
   - 拍卖成功/流标处理：物品/金币邮件返还
2. **拍卖分类与筛选**：
   - 分类：武器、防具、消耗、其他、现金
   - 筛选条件：职业、等级、属性、稀有度
   - 排序：价格、时间、等级
3. **拍卖费用与税收**：
   - 上架手续费（按物品价值比例）
   - 交易税（拍卖成功后扣除）
   - 保管费（过期物品暂存）
4. **拍卖历史与统计**：
   - 玩家拍卖记录查询
   - 成交价格统计（市场物价参考）
   - 热门物品排行
5. **Web端拍卖浏览**：
   - 网页/小程序浏览拍卖物品
   - 手机端竞拍提醒
6. **数据库设计**：
   ```sql
   CREATE TABLE `auctions` (
     `id` BIGINT PRIMARY KEY AUTO_INCREMENT,
     `seller_id` INT NOT NULL,
     `item_id` INT NOT NULL,
     `item_data` TEXT NOT NULL COMMENT '物品序列化数据',
     `start_price` INT NOT NULL,
     `current_bid` INT DEFAULT 0,
     `current_bidder_id` INT,
     `buy_now_price` INT,
     `duration` INT NOT NULL COMMENT '拍卖时长(小时)',
     `expire_time` DATETIME NOT NULL,
     `status` TINYINT DEFAULT 0 COMMENT '0:进行中 1:成交 2:流标 3:取消',
     `created_at` DATETIME DEFAULT CURRENT_TIMESTAMP
   );
   ```
7. **代码实现参考**：
   - 现有的Fredrick/商店相关代码
   - 背包物品序列化：`client.inventory`包
   - 邮件/快递系统：`net.server.channel.handlers.DueyHandler`

## 三、反外挂方向

### 3.1 自动封禁系统完善

**现状**：有基础封禁功能，但缺乏自动化检测和封禁。

**目标**：实现多维度自动检测外挂行为，自动执行封禁处罚。

**实现思路**：
1. **封禁维度扩展**：
   - 账号封禁
   - HWID（硬件ID）封禁：获取硬盘序列号、MAC地址等硬件特征
   - IP封禁（支持IP段）
   - MAC地址封禁
   - 机器码封禁
2. **封禁类型分级**：
   - 临时封禁（几分钟/几小时/几天）
   - 永久封禁
   - 禁言
   - 限制交易/移动/攻击
3. **自动检测触发点**：
   - 数据包异常检测（见3.2）
   - 行为异常检测（见3.3）
   - 聊天关键字检测（广告、辱骂）
   - 举报系统人工审核
4. **封禁记录与申诉**：
   - 封禁日志：原因、时间、触发检测类型
   - 封禁公告/通知（登录时提示）
   - 申诉渠道（Web后台提交申诉）
   - 解封审批流程
5. **数据库表设计**：
   ```sql
   CREATE TABLE `bans` (
     `id` INT PRIMARY KEY AUTO_INCREMENT,
     `account_id` INT,
     `character_id` INT,
     `hwid` VARCHAR(100),
     `ip` VARCHAR(50),
     `ban_type` TINYINT COMMENT '1:账号 2:HWID 3:IP 4:角色',
     `reason` VARCHAR(500),
     `ban_duration` BIGINT COMMENT '封禁时长(毫秒),0=永久',
     `banned_at` DATETIME DEFAULT CURRENT_TIMESTAMP,
     `banned_by` VARCHAR(50) COMMENT 'GM账号/自动检测系统',
     `expires_at` DATETIME,
     `status` TINYINT DEFAULT 1 COMMENT '1:生效 2:已解除'
   );
   ```
6. **代码实现参考**：
   - 账号封禁：`dao.entity.Accounts`的banned字段
   - GM封禁命令：`client.command.Commands`
   - 登录验证：`net.server.login.LoginServer`

### 3.2 数据包校验

**现状**：基础加密已实现，但缺乏数据包内容的合法性校验。

**目标**：对客户端发送的数据包进行严格校验，过滤篡改的非法数据包。

**实现思路**：
1. **数据包完整性校验**：
   - 包长度校验：防止超长包或截断包
   - 字段范围校验：位置坐标、血量、等级等数值在合理范围
   - 类型校验：确保字段类型符合预期（数字/字符串/枚举）
2. **状态校验**：
   - 移动校验：移动速度、移动距离不能超过角色能力上限
   - 攻击校验：攻击范围、攻击速度、伤害值合理性验证
   - 物品操作校验：物品来源、数量、背包位置合法性
   - 技能使用校验：技能未学习、冷却未结束、MP不足时拒绝
3. **时序校验**：
   - 数据包时间戳/序列号校验
   - 防止重放攻击（重复发送相同数据包）
   - 操作频率限制：攻击频率、吃药频率、移动频率
4. **位置校验（反飞天/穿墙）**：
   - 记录玩家上一位置，计算移动距离是否合理
   - 校验玩家坐标是否在地图可行走区域（ foothold ）
   - 校验玩家高度（防止飞天、悬空）
   - 检测瞬间长距离移动（瞬移外挂）
5. **伤害校验**：
   - 根据玩家属性（力量/攻击/技能等级）计算理论伤害范围
   - 检测一击必杀（伤害远超怪物血量）
   - 检测无敌（怪物攻击不掉血）
6. **校验失败处理**：
   - 首次异常：警告、记录日志
   - 多次异常：强制断开连接

### 3.3 行为检测

### 3.4 HWID/IP/MAC多维度封禁

**现状**：主要是账号封禁，容易被绕过（新建小号）。

**目标**：实现多维度关联封禁，提高外挂作弊成本。

**实现思路**：
1. **硬件信息采集**：
   - 客户端采集HWID（硬件唯一标识）：
     - 硬盘序列号
     - CPU ID
     - 网卡MAC地址
     - 主板序列号
   - 加密上传到服务端
   - 防止伪造（客户端加密校验）
2. **关联封禁策略**：
   - 同HWID下有账号被封，新账号标记为风险账号
   - 同IP段短时间大量注册账号，封禁IP段
   - 关联账号追踪：一个账号开挂，同设备/同IP所有连带账号
3. **封禁级别配置**：
   - 轻度违规：仅当前账号
   - 中度违规：账号+HWID
   - 严重违规：账号+HWID+IP
   - 工作室/广告：IP段封禁
4. **风险等级机制**：
   - 新账号（注册时间短）风险提示
   - 有违规记录设备登录新账号需要验证
   - 高风险账号限制交易、世界聊天
5. **绕过检测**：
   - 检测虚拟机运行
   - 检测常见外挂进程
   - 检测客户端内存篡改（需客户端CRC校验）
6. **白名单机制**：
   - GM账号白名单
   - 可信网吧/机房IP白名单
   - 误封申诉解封加白
7. **实现注意事项**：
   - 硬件信息需隐私合规，加密存储
   - IP封禁需谨慎，避免误封网吧/小区等共享IP
   - 提供申诉渠道避免误封导致玩家流失
8. **代码实现参考**：
   - 登录时信息采集：`net.server.login.LoginPacketHandler`
   - 客户端发送特殊数据包上报硬件信息

## 四、性能优化方向

### 4.1 多频道架构

**现状**：单LoginServer，多ChannelServer但可能在同一进程内。

**目标**：实现频道可独立部署、水平扩展，支撑更多在线玩家。

**实现思路**：
1. **频道独立部署**：
   - 每个Channel作为独立Java进程
   - LoginServer作为入口，返回频道列表和连接信息
   - 频道之间通过网络通信（Netty/RPC）
2. **跨频道通信**：
   - 跨频道聊天：频道1玩家私聊频道2玩家
   - 跨频道好友在线状态同步
   - 跨频道组队/公会信息同步
   - 使用Redis或消息队列（如RabbitMQ）做跨进程消息
3. **频道配置动态化**：
   - 动态增减频道无需重启整个服务端
   - 频道状态监控（负载、在线人数）
   - 负载均衡：登录时自动推荐人数少的频道
4. **频道迁移**（进阶）：
   - 玩家不换号跨频道移动
   - 角色数据在频道间迁移（需要数据一致性保障）
5. **架构方案**：
   ```
   ┌─────────────┐
   │  Client(s)  │
   └──────┬──────┘
          │
   ┌──────▼──────┐
   │ LoginServer │ (独立进程)
   └──────┬──────┘
          │
   ┌──────┼──────┬──────────┐
   │      │      │          │
   ┌▼┐   ┌▼┐   ┌▼┐  ...   ┌▼┐
   │C1│   │C2│   │C3│      │Cn│  ChannelServer（独立进程）
   └─┘   └─┘   └─┘       └─┘
          │
          └──────┬──────┘
                 │
          ┌──────▼──────┐
          │  Redis/DB   │ 共享缓存、数据库
          └─────────────┘
   ```
6. **代码实现参考**：
   - 现有Channel初始化：`net.server.Server`
   - World管理：`net.server.world.World`
   - 跨服通信可参考Redis发布/订阅模式

### 4.2 玩家分片

**现状**：单频道内所有玩家在同一处理流程，玩家多时全局广播/更新压力大。

**目标**：按地图/区域分片处理，降低单频道压力。

**实现思路**：
1. **地图分片（Map Sharding）**：
   - 热门地图（如自由市场、射手村）单独线程处理
   - 冷门地图合并处理
   - 每张地图独立的更新循环：怪物刷新、移动同步
2. **AOI（Area of Interest）算法**：
   - 玩家只接收视野范围内其他玩家/怪物的移动包
   - 减少无效的全局广播
   - 视野范围根据地图大小动态调整
3. **附近玩家更新优化**：
   - 不是每次玩家移动都广播给所有人
   - 定期更新附近玩家列表
   - 只发送进入/离开视野、显著动作（攻击/技能）
4. **掉落/道具优化**：
   - 只在玩家视野内显示掉落物
   - 远离的掉落物不发送给客户端
   - 掉落物及时清理
5. **消息分级**：
   - 高优先级消息：攻击、移动、聊天（及时发送）
   - 低优先级消息：血量更新、Buff图标（批量/延迟发送）
6. **代码实现参考**：
   - 地图内玩家集合：`server.maps.MapleMap.players`
   - 广播方法：`MapleMap.broadcastMessage()`
   - 移动处理：`MovePlayerHandler`中附近玩家更新

### 4.3 缓存优化

**现状**：WZ数据有缓存，但玩家数据、配置数据频繁查询数据库。

**目标**：多级缓存架构，减少数据库查询，提升响应速度。

**实现思路**：
1. **本地缓存（Caffeine/Guava Cache）**：
   - 热点数据缓存：
     - 在线玩家角色数据（内存中，不实时落库）
     - 物品数据、技能数据（WZ缓存）
     - 配置表（服务器配置、掉率表）
   - 缓存过期策略：
     - LRU淘汰
     - 定时刷新
     - 写后异步刷新
2. **分布式缓存（Redis）**：
   - 跨频道共享数据：
     - 好友在线状态
     - 公会信息
     - 拍卖物品列表
     - 排行榜数据
   - Session数据：
     - 登录Token
     - 频道登录状态
3. **缓存一致性**：
   - 玩家数据：定时批量持久化到数据库
   - 写策略：先更新缓存，异步批量写DB（Write Behind）
   - 关键数据（充值、购买）：先写DB再删缓存
4. **数据库查询优化**：
   - 避免N+1查询：使用批量查询
   - 复杂查询结果缓存
   - MyBatis-Flex二级缓存开启
5. **缓存监控**：
   - 缓存命中率统计
   - 缓存大小监控
   - 慢查询日志（数据库+缓存）
6. **代码实现参考**：
   - WZ缓存：`provider.wz.XMLWZFile`缓存机制
   - Druid连接池监控（已有）
   - 角色自动保存：现有定时保存任务，可改为批量异步

### 4.4 数据库优化

**现状**：单MySQL数据库，高并发下可能成为瓶颈。

**目标**：数据库架构优化，支撑高并发读写。

**实现思路**：
1. **索引优化**：
   - 分析慢查询日志，添加缺失索引
   - 常用查询字段索引：
     - `characters(account_id, world)`
     - `inventoryitems(character_id, inventorytype)`
     - `buddylist(character_id)`
     - `guilds(guild_id)`
   - 避免过度索引影响写入
2. **SQL优化**：
   - 避免SELECT *，只查询需要字段
   - 大表分页优化（使用游标而非OFFSET）
   - 批量操作：批量插入、批量更新
   - 避免在大表做JOIN，应用层做组装
3. **读写分离**：
   - 主库：写操作（INSERT/UPDATE/DELETE）
   - 从库：读操作（SELECT）
   - 使用Sharding-JDBC或MyCat中间件
4. **分库分表（进阶）**：
   - 水平分表：
     - 按角色ID分表：inventoryitems、buddylist、chatlog
     - 按时间分表：登录日志、交易记录、聊天记录
   - 垂直分库：
     - 游戏主库（角色、物品、怪物）
     - 日志库（操作日志、登录日志）
     - 统计库（排行榜、数据分析）
5. **连接池调优**：
   - Druid连接池参数优化：
     ```yaml
     druid:
       initial-size: 10
       max-active: 100
       min-idle: 20
       max-wait: 60000
       time-between-eviction-runs-millis: 60000
       min-evictable-idle-time-millis: 300000
     ```
6. **数据库运维**：
   - 定期慢查询分析
   - 定期备份（binlog + 全量备份）
   - 主从复制延迟监控
7. **代码实现参考**：
   - Mapper位于`dao.mapper`包
   - Druid监控页面（如有配置）
   - 现有Flyway迁移脚本：`db/migration/`

### 6.3 备份恢复

**现状**：需手动备份数据库，缺乏自动化备份。

**目标**：自动化备份策略，数据丢失可快速恢复。

**实现思路**：
1. **自动备份策略**：
   - **全量备份**：每日凌晨自动执行mysqldump
   - **增量备份**：开启binlog，定时备份binlog
   - **配置文件备份**：scripts目录、wz目录、application.yml
   - **备份保留**：保留最近7天每日备份、最近4周每周备份、最近12月每月备份
2. **备份存储**：
   - 本地备份（服务器磁盘）
   - 异地备份：OSS对象存储、另一台服务器
   - 定期校验备份文件完整性（可正常恢复）
3. **恢复流程文档**：
   - 数据库损坏恢复步骤
   - 误操作数据回滚（通过binlog）
   - 整台服务器故障迁移流程
4. **定时任务脚本**：
   ```bash
   #!/bin/bash
   BACKUP_DIR=/data/backup
   DATE=$(date +%Y%m%d_%H%M%S)
   mysqldump -u root -p$MYSQL_PWD beidou | gzip > $BACKUP_DIR/beidou_$DATE.sql.gz
   # 删除7天前备份
   find $BACKUP_DIR -name "*.sql.gz" -mtime +7 -delete
   # 同步到OSS
   ossutil cp $BACKUP_DIR/beidou_$DATE.sql.gz oss://your-bucket/backup/
   ```
5. **Web后台备份管理**：
   - 一键手动备份
   - 备份列表查看/下载
   - 一键恢复（选择备份文件）
   - 备份状态监控
6. **注意事项**：
   - 备份账号权限最小化（只需要SELECT权限）
   - 加密敏感备份数据
   - 定期演练恢复流程，确保备份可用

## 九、移动支持方向

### 9.1 移动端API

**现状**：只有Web管理后台API，缺少面向玩家移动端的API。

**目标**：提供玩家端移动API，支持小程序/App辅助功能。

**实现思路**：
1. **API分类设计**：
   - **账号相关**：
     - 手机端登录/注册
     - 角色列表查询
     - 角色详情（装备、属性、背包快照）
   - **社区相关**：
     - 排行榜查询
     - 公告查看
     - 邮件查看/发送
     - 好友列表、在线状态
     - 公会信息、聊天（可选）
   - **交易相关**：
     - 拍卖浏览、搜索
     - 竞拍、一口价购买
     - 个人商店浏览（可选）
   - **商城相关**：
     - 商城道具浏览
     - 点券余额查询
     - 购买道具（发放到游戏内商城背包）
2. **API安全**：
   - 独立的认证体系（JWT Token）
   - 接口限流（防止刷接口）
   - 敏感操作（购买、交易）二次验证
   - HTTPS加密传输
3. **数据同步问题**：
   - 在线玩家数据在内存，API需要能读取内存数据（跨频道）
   - 离线玩家直接读数据库
   - 缓存一致性
4. **推送通知**：
   - 拍卖被出价/成交推送
   - 好友上线推送
   - 活动开始推送
   - 服务器维护公告推送
5. **代码实现参考**：
   - 现有Controller可扩展，新增`/api/mobile/`路由
   - Spring Security单独配置移动端API权限
   - 参考现有`AuthController`认证模式

### 9.2 小程序管理

**现状**：没有移动端应用。

**目标**：开发微信小程序/抖音小程序，方便玩家随时查看和管理账号。

**实现思路**：
1. **小程序功能规划**：
   - **首页**：服务器状态、在线人数、公告、活动
   - **角色**：角色信息、装备展示、背包查看
   - **排行榜**：各排行浏览、自己的排名
   - **拍卖**：搜索、竞拍、一口价、我的拍卖
   - **商城**：浏览商品、限时活动、购买记录
   - **社区**：论坛、好友聊天、公会信息
   - **个人中心**：账号设置、密码修改、反馈
2. **技术选型**：
   - 微信小程序原生开发 / uni-app跨端
   - UI组件库：Vant Weapp / uView
   - 请求封装、登录态管理
3. **微信登录对接**：
   - 微信授权登录获取openid
   - 绑定游戏账号
   - UnionID统一识别
4. **GM管理小程序**（管理端）：
   - 服务器监控面板（手机看状态）
   - 在线玩家列表
   - 封禁/解封操作
   - 发公告、发物品
   - 紧急维护一键关服
5. **消息推送**：
   - 微信订阅消息推送
   - 服务通知（拍卖、奖励）
6. **开发流程**：
   - 先完善移动端API（9.1）
   - 再开发小程序前端
   - 提交微信审核发布
7. **代码实现参考**：
   - 后端提供RESTful JSON API
   - 小程序项目独立仓库（类似gms-ui）

## 其他方向（可探索）

除以上方向外，还有一些可探索的方向：
- **账号安全**：手机绑定、邮箱验证、二次密码、异地登录提醒
- **客服系统**：游戏内工单系统、GM在线服务
- **反沉迷系统**：符合国家规定的未成年人防沉迷
- **直播相关**：游戏内直播、观战系统
- **创意工坊**：玩家自定义内容（自制地图、活动）
- **数据迁移工具**：其他服务端数据迁移到BeiDou

## 开发优先级建议

如果是新搭建服务器，建议按以下优先级开发：
1. **P0（基础完善）**：基础转职技能、常见副本、任务、交易、反外挂基础
2. **P1（运营基础）**：Web后台完善、GM工具、日志监控、备份
3. **P2（内容扩展）**：新职业、新地图、更多副本、活动系统
4. **P3（性能优化）**：多频道、缓存、数据库优化（玩家多了再做）
5. **P4（社区/生态）**：排行榜、成就、论坛、小程序
6. **P5（高级特性）**：多服务器集群、跨服玩法、机器学习反外挂

根据服务器规模和玩家需求灵活调整开发计划。
